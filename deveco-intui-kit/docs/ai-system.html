DevEco Code、CodeGenie 以及 IDE 里所有 AI 能力共用的一套视觉与交互：从标识、用色、图标，到代码高亮、进行态、组件和输入框。它只做一件事：让开发者写代码时，随时回答得出下面三个问题。每一条规则旁边都有一张「在 IDE 里的样子」。

这是谁写的？AI 写的代码、改的界面有同一个记号；人改的不打标。
它在干什么？每个进行态都说具体在读什么、跑什么、已用多久。
轮到我了吗？只有「在等你」会亮琥珀色，其余进行态都安静。

原则

01

来自 Apple HIG · Generative AI，逐条翻译成开发者在 IDE 里的一幕。每条原则都要能挂到一个开发任务上，挂不上的不收。

HIG · Keep people in control

改动旁边永远有「编辑 · 退回 · 重试 · 调整」，并告诉你改动已生效

在做
让 AI 把登录页适配深色模式
卡在
它一次改了 5 个文件，不确定哪些真的写进去了；不满意只能 git checkout 全撤
这样解
回答卡底部写「已写入 5 个文件」，每个文件单独可退

HIG · Clearly identify when and where you use AI

AI 做的，在代码、画布、时间轴上用同一个记号；人改的不打标

在做
审同事提的 PR，里面一半是 AI 生成的
卡在
分不清哪段该重点看，只能逐行猜
这样解
gutter 竖条标出 AI 段落，悬停看是哪一步生成的

HIG · Set clear expectations

空输入框给能直接点的示例，按当前文件生成

在做
第一次打开 DevEco Code
卡在
不知道它只能聊天，还是能直接改工程、跑模拟器
这样解
示例写「给 LoginPage 加手机号校验」，点一下就能跑

HIG · On-device vs. server · privacy

本机还是云端，常驻显示；要把代码发出去之前先说

在做
在公司内网项目里问 AI
卡在
不确定代码有没有被传出去，干脆不敢用
这样解
输入框底栏常驻「本机 / 云端」图标，切云端前提示一次

HIG · Factor processing time · specific, reassuring feedback

等待要说人话：在读哪个文件、跑哪个工具、已用多久

在做
发出需求后盯着面板等
卡在
只有「处理中…」，不知道是在读工程还是卡死了
这样解
显示「正在读 LoginPage.ets 和 3 个 @State · 4 s」

HIG · Let people share feedback · offer alternate versions

反馈放在不打断的地方；备选版本并排给，不连环弹窗

在做
拿到答案，急着回到代码
卡在
弹窗问「这个回答有帮助吗」挡住编辑器
这样解
点赞点踩淡色放卡片右下角，点不点都行

HIG · Ask before taking destructive or irreversible actions

删文件、改签名配置、在真机上装包、执行 shell 之前停下来问——这是唯一用琥珀色的时刻

在做
让 Agent 修构建报错，自己去查文档
卡在
回来发现它跑了 clean、还改了签名配置，调试证书没了
这样解
审批卡先讲清影响和能不能撤回；状态栏琥珀点提醒你回来

用色

03

智能色独立于品牌蓝：蓝色 #3574F0 只留给「你要按的」——主按钮、聚焦、链接；智能色只表示「这是 AI 做的 / AI 正在做」。一道紫罗兰 → 兰紫 → 玫瑰的光，参考 Apple 冷暖多色光、Gemini 蓝紫、CodeGenie 紫光晕与鸿蒙光感。

当前主题：浅色· 切右上角看另一套

谁用什么色

品牌蓝

主按钮（每屏最多一个）、聚焦环、链接、当前选中的小标记。

智能色

AI 来源记号、进行态、标识。字与图标用纯色 --ai-ink。

琥珀

只给「在等你」：审批、需要你选。唯一会脉冲的颜色。

绿 / 红

增删、成功、失败。AI 改的代码也用它们，来源只靠 gutter 星芒。

四条用色规则

小字用纯色，渐变只做三件事

渐变只用于：标识、生成中的输入框光、进行中的光环。不做大面积渐变底，不做渐变字。

在做
扫一眼 AI 面板，找它改了哪几处
卡在
渐变小字在深色下糊成一片，读不清文件名
这样解
字一律 --ai-ink，两套主题都过 AA（≥ 4.5）

一屏最多两处渐变

通常是「标识 + 正在发生的那一处」。第三处出现时，说明有东西不该在发光。

在做
AI 在跑，你同时在看代码
卡在
面板、按钮、标签到处是彩色光，眼睛不知道看哪
这样解
光只留给正在发生的那一处，其余回到中性

智能色 ≠ 品牌蓝

蓝色 = 你要按的；紫色 = AI 做的。两者不能互换。

在做
AI 给了修复建议，旁边是要你按的按钮
卡在
都是蓝色，分不清哪个是 AI 的提议、哪个是要你执行的操作
这样解
AI 提议用智能色标来源，要你按的仍是蓝色主按钮

琥珀只给「在等你」

它是唯一需要抢注意力的态，也同步到状态栏和窗口标题。

在做
AI 跑长任务，你切去写别的文件
卡在
它停下来等授权，你十分钟后才发现
这样解
琥珀点脉冲；其余进行态都安静，所以它一亮你就知道

高亮

06

回答「这是谁写的」。原则：只标 AI，人改的是默认不打标；标记要淡到不影响读代码，淡到接受之后自己消失；但任何时候悬停都能查到来源。

AI 生成的代码行

gutter 渐变竖条 + 极淡底色；接受后 3 s 淡出；悬停竖条看来源。

在做

卡在

这样解
接受前：竖条 + 极淡底；接受后 3 s 淡出不碍眼；悬停 gutter 随时查来源

进行态

07

回答「它在干什么」和「轮到我了吗」。八个状态，一台状态机；每态规定视觉、文案、动效时长，以及系统开了「降低动效」时的替代——替代的原则是把动的信息改成字（步骤数、已用时）。

待命→ 理解中→ 调用工具⇄ 生成中→ 在设备上验证→ 完成→ 待命

专题：设计稿到代码之后，可视化修改 × AI Coding

11

D2C 把画板变成了 DetailPage.ets，但真正耗时间的是之后：设计师说「卡片再松一点、价格大一号、按钮换胶囊」，十几处细改。它们会从三只手进来。

在做
D2C 出了商品详情页，正对着设计走查意见逐条改
要做成
改完的页面在手机、折叠屏、平板上都对，代码仍然走 token 和组件，设计稿也同步
卡在
拖一下写出裸值、问 AI 又慢又不准、设计稿越改越旧、最后说不清哪处是谁改的

三只手，各自卡在哪

直接操作

在 Previewer、模拟器、或鸿蒙电脑上的真机镜像窗口里拖、调数值。

好零延迟、确定，所见即所得。
卡写出 .padding(13) 这种裸值，绕开了 token 和组件；改一处，别处的同款卡片不跟。

说 / 用笔圈

交给 AI：「这块改成两列」「按钮换胶囊」。

好结构性改动一句话搞定。
卡小改动也走 AI：等 10 秒，还可能改到别处；「再大一点」到底是几？

直接改代码

在编辑器里改 ArkTS。

好精确，能用上工程里的一切。
卡先要找到预览上这块对应哪一行；改完设计稿不知道。

外壳建议

13

这一轮不改 IDE 外壳（demos/_shared/frame.js）。下面几条是 Islands 与 Xcode 27 的方向落到外壳上时的建议，按收益排序，都以「少一层装饰、少一次切换」为准。

工具窗与编辑器改成 Islands：圆角块 + 间隙

工具窗、编辑器、底部面板各自圆角 8–10，之间留 4–6px 间隙露出窗口底色，去掉 1px 分隔线；可选「工具窗用不同底色」突出编辑器。依据：JetBrains Islands（2025.3 默认）。

Agent 对话可以开成编辑器标签页 / 分栏

右侧工具窗保留；长任务可拖成编辑器标签，和代码并排；Agent 改过的文件列在对话右侧。依据：Xcode 27。

构建 / Agent 活动写在顶栏标题下

一行字（「DevEco Code · 正在构建 entry」），「在等你」的琥珀点也放这里；状态栏只留编码、行列等静态信息。依据：Xcode 27。

顶栏只留一个 ‹✦› 入口，放在运行配置旁

与 Xcode 27 把 Agent 入口放在工具栏中间同理；插件图标不借星芒。

输入时的实时问题更淡，保存 / 构建后再给全强度

和「AI 生成行接受后淡出」同一思路：正在打字时别被打断。依据：Xcode 27 的预测性问题。
