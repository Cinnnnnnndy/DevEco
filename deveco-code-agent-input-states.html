DevEco Code Agent 输入框 · 场景与状态说明

只覆盖 CodeGenie/Agent 面板输入框本身的交互——不含会话区消息气泡、Diff 卡等结果呈现。九个场景按"触发条件 → 状态变化 → 反馈/边界"组织，每组配一段设计依据。

2026-09-17·DevEco 6.0.2.670 现状 + 竞品证据推演

场景一 · 输入与编辑

现状详细化

管什么：多行输入、粘贴、拖拽、容量提示——后面 @、/、语音、意图确认都挂在这一层容器上

空态
面板打开/无历史输入。只显占位符，发送键灰不可点，无紫色描边光晕。
聚焦态
点击编辑区。描边变紫色渐变光晕，无论有无文字；失焦后光晕消失，不受未发送内容影响。
90% 容量警示
≥90% 时空心圆从灰转橙；hover 显百分比。达 100% 后发送键置灰，tooltip 提示"内容过长，请删减或移除上下文"。

设计依据：输入与编辑是所有场景的地基——多行、粘贴、拖拽、容量提示要先稳定，后面的 @、/、语音、意图确认才有可挂靠的容器。这一层是主流 AI 编程工具输入框的通行标配，未见 project 内竞品分析文档对多行/粘贴/拖拽做过逐家专项核实，按通行实现补齐；"粘贴代码不自动转代码块"与"90% 阈值进度环"两点是本文自身的设计判断，不是对某一竞品的复现（已列入已知局限）。

现状详细化

管什么：把占位符里"Type @ to add context"的承诺落成完整交互——搜索分类、chip 管理、上限、取消

光标处输入 @，或点击上排 "@ Add Context" chip。列表按最近文件/当前打开标签/项目全文件/符号分组。
搜索过滤
最近文件
module.json5

场景三 · / 切换功能

现状详细化

管什么：把占位符里"Type / to switch between functions"落成真实菜单——9 个功能项，选中后变成输入框内的功能 pill

呼出菜单
HarmonyOS Ask提问、查资料、读代码
HarmonyOS Act自主执行、改代码、跑命令
Generate UI Code按描述生成 ArkUI 界面
Generate Code生成函数/模块代码
Complete Code补全当前光标处代码
Inline Chat编辑器内联对话
Explain Code解释选中代码
Smart Fix定位并修复报错
Smart Profiling性能分析建议
光标处输入 /，弹出 9 个功能项，图标+名称+一句说明；HarmonyOS Act 与 Ask 互斥，其余 7 项是"一次性"功能，选中后立即替换为 pill。
选中后
Generate UI Code
"/文本"被替换为一枚可关闭的功能 pill；占位符与模式选择器联动切换（此例切到 Act），点 × 可撤销回普通输入。

设计依据：同样源自 DevEco 现状——占位符里已经承诺"Type / to switch between functions"，本场景把这句提示落成真实菜单：9 个功能项取自 CodeGenie 欢迎态的九个 chip（HarmonyOS Ask / Act、Generate UI Code、Generate Code、Complete Code、Inline Chat、Explain Code、Smart Fix、Smart Profiling），选中后转 pill、可关闭撤销，按通行实现补齐，不构成独占性设计。

场景四 · 模型与深度思考

现状详细化

管什么：模型切换与"深度思考"开关分层放置，避免与聊天模式选择器混为一谈

模型下拉
deepseek-v4-flash默认 · 速度优先
deepseek-v4-pro质量优先
pangu-5.5盘古大模型
GLM-Enterprise未连接
与"HarmonyOS Ask/Act"模式选择器左右并列、各占一格，不混进同一个下拉；未连接的模型置灰但仍列出，点击引导去设置里配置。
深度思考开关
关 / 开左右对照：灰描边 → 蓝底高亮，开启后当前会话使用更长思维链，不改变已选模型。
能力不匹配
切到不支持深度思考的模型后，开关自动禁用（不是隐藏），保留 tooltip 说明原因，避免用户以为是 bug。

设计依据：模型选择器、聊天模式选择器、深度思考开关"三层分开放"，与《竞品分析_模型与API管理界面_九款IDE_202609》总结的主流形态一致——参考竞品：VS Code Copilot、Cursor、Trae、Zed、Antigravity 均把"选模型"与"选模式/选功能"拆成两个独立控件，而不是塞进一个下拉；深度思考开关随模型能力禁用的做法同样是这几家的通行实现。

场景五 · 语音输入

新方案提案

管什么：DevEco 现状没有语音入口；本场景是全新提案——补上"全程不碰键盘"的闭环

入口
麦克风图标常驻发送键左侧，空态为灰色线稿；短按切换录音开关，长按为"按住说话"（双模式）。
录音态
正在聆听…00:07
textarea 让位给波形+计时；模式/模型选择器锁定，避免录音中误触切换；再次点击麦克风或说出"发送"结束录音。
转录态
识别文本流式写回 textarea（半透明表示"还在转写"），完成后可直接编辑再发送，不强制立即提交。

设计依据：三家竞品（Claude Code、VS Code、Cursor）已有原生语音输入，DevEco/CodeGenie 现状完全空缺——这是本文九个场景里唯一"从零到一"的提案。交互细节参考 Claude Code voice dictation 的 hold（长按）/ tap（点按）双模式，以及"项目名、分支名自动加入识别提示词"的做法，本文暂未展开该细节，留作后续设计。

场景六 · 意图确认与计划预览

新方案提案

管什么：接单前先亮计划、执行中有疑问不停工——DevEco 现状两者都缺

计划预览态
看看 entry 模块下登录页的实现，把验证码倒计时逻辑抽成 hook
✓读取 LoginPage.ets 与相关组件
✓定位倒计时相关状态与副作用
●抽取 useCountdown 自定义 hook
替换调用点并跑一遍编译
只读展示原始指令 + 步骤清单（已完成/进行中/待办），发送按钮变成 Proceed；输入框仍可打字追加意见，不锁定。
执行中需澄清 · 不停工
1 个问题待确认
验证码倒计时是否需要在页面切换后继续计时（后台保活）？
澄清问题以卡片形式插入回答流，不弹窗、不暂停后台任务；输入框与终止键保持可用（此例仍在生成中），点选项或直接打字都能继续对话。

设计依据：六家竞品（Claude Code、Xcode、Android Studio、Cursor、Codex、Qoder）在"互动式意图确认"上已基本补齐，仅剩一格——问的时候不停工，目前只有 Cursor、Codex 支持。计划预览的 Submit-comments/Proceed 结构参考 Android Studio Planning Mode；执行中非阻塞澄清参考 Codex 的设计说明"Answer questions inline while Codex continues working in the background, without losing your main draft"。本场景把这两点拼进同一个输入框容器，属于新方案提案，尚未经过评审（已列入已知局限）。

场景七 · 发送、生成中与终止

现状详细化

管什么：让用户"看得见、管得住"——空输入不可发、生成中控件锁定、终止后可复核

空输入禁用
正文与 chip 均为空时发送键置灰不可点，避免空请求；有内容（哪怕只有一个 chip）即可发送。
生成中
发送键变红描边"停止"图标；上下文、模式、模型、语音全部锁定，唯独停止键保持可点——防止生成过程中改变前提导致状态不一致。
终止后
已停止
控件全部解锁；已生成的部分内容保留在回答区（不回滚），"已停止"是短时提示，几秒后自动消失。

设计依据：呼应上半年用户调研的核心发现——用户在 AI 执行过程中最关注"任务进度"（58.37%）与"当前执行阶段"（55.66%），此场景属于"掌控感设计"：生成中控件锁定让用户知道"现在改不了前提"，红色停止键与终止后的"已停止"回执让用户随时能中断、随时确认中断已生效。数据引自《用户研究结论_上半年鸿蒙开发者调研_202609》。

场景八 · 异常与边界状态

现状详细化

管什么：网络异常、模型不可用、会话加载中——三类边界状态直接回应用户调研里的失望场景

网络异常
发送失败：网络连接异常，请检查网络后重试
草稿原样保留在输入框，不清空、不丢失；错误条给出原因与"重试"按钮，而不是让用户重新打一遍字。
无可用模型
模型按钮变红并显示"未配置"，点击直达设置页而不是弹出空列表；发送键同步禁用。
会话加载中
骨架屏替代空白等待，输入框保持可见但禁用并标注原因，避免用户误以为可以正常输入却没反应。

设计依据：四类边界状态直接回应用户调研里反复出现的失望场景——"进去之后一个多小时没反应……不知道它状态是红的还是正常的"（寻找新的大陆）反映的是"看不出状态"的焦虑，对应本场景的骨架屏与错误条；"历史记录……每次都得把它点开、再到里面去找"（格力）反映的是加载/恢复过程缺乏反馈。原文引自《用户研究结论_上半年鸿蒙开发者调研_202609》。

场景九 · 键盘快捷键一览

现状详细化

管什么：汇总输入框内的按键约定，全局呼出与语音按键待与 Windows 版核实冲突

Enter发送当前输入
Shift+Enter换行，不发送
@呼出添加上下文菜单
/呼出功能切换菜单
Esc关闭当前弹出的 @ / / 菜单
↑在空输入框按下，回填上一条发送内容
Ctrl+Shift+A全局呼出 Agent 输入框（新增，待核实冲突）
Ctrl+Shift+V全局呼出语音输入（新增，待核实冲突）
前 6 行为 AI 输入框通行按键约定，继承自 DevEco 现状的隐含约定；后 2 行全局快捷键为本文新增。

设计依据：Enter / Shift+Enter / @ / / / Esc / ↑ 是主流 AI 编程工具输入框的通行按键约定，沿用 DevEco 现状的隐含约定，未见逐家竞品核实来源；全局呼出快捷键与语音按键为本文新增，需与 Windows 版负责同学核实是否与已有全局快捷键冲突（已列入已知局限）。
