输入框下的「钢琴键」

返回研究分类 启动页

DevEco Code 的输入框下方常驻一排键帽：Enter发送、ShiftEnter换行、@上下文、/功能、↑上一条。 这一页只定一件事：这排「钢琴键」该显示几个、什么时候出现、变成什么。对照 Claude Code、Codex CLI、WorkBuddy、Cursor、Gemini CLI 的一手实现，收敛成一套可落地的显示规则与验收条件。

它有两个工作，别用一套键 空输入时教发现（@ /），有字时教动作（Enter发送），生成中只教退出（Esc）。
常驻整行＝每帧都在抢注意力 超过三个键，边际信息趋零。键帽有边界感，比占位符更像「可点的东西」——越全越没人读。
换键可以，换行高不行 键帽行的高度一变，输入框就被顶得上下跳。内容随便换，高度必须恒定。

01 它是什么 · 六个显示维度

六个独立决定

「钢琴键」不是一种组件，是六个独立决定叠出来的结果。每一家产品其实只在这六个格子里各选了一个值——分开看，才知道自己改的是哪一格。

维度取值为什么这一格决定成败
D1 位置 输入框内 bar · 输入框正下方独立行 · 终端 footer · 全局状态栏 决定它是否推内容。终端没有 composer，footer 是唯一的家；GUI 里「正下方一行」最贴近，但最容易被输入框高度顶动。
D2 常驻度 常驻整行 · 情境化 1–3 键 · 默认隐藏只进 ? 决定每帧占多少视觉带宽。常驻整行＝每帧重读一遍；三天后没人看，但它还在抢位置。
D3 数量 1–2 · 3–5 · 全量 8+ 键帽是扫读不是阅读。超过三个，扫读变成找读——「要的那个键在第几个」。
D4 形态 键帽（有边界）· 纯文本 · 仅符号 键帽可扫、像可点目标，但抢注意力；纯文本安静但看不清是键。符号（⌃⇧⌥⌘）省地方，跨平台有歧义。
D5 状态切换 静态 · 随输入状态（空 / 有字 / 生成中 / 在等你） 「生成中 Esc 停止」是唯一必须做的切换。做了状态切换，常驻数量就可以砍。
D6 自定义 无 · ? 全量面板 · /keybindings 可改 全量面板把「看不见的键」从常驻区挪走；可改键位让重度用户自己管，轻度用户根本不需要知道。

为什么它是「提示」里最容易变噪音的一种

键帽有边界感。.ai-kbd 的圆角底盒比占位符更像可点的控件，视线会被吸过去——每生成一行它就在那里，每帧都在和「正在写的代码」抢一次。

常驻 = 边际信息趋零。第 1 天看它学会 Enter 发送，第 3 天起它只是占位。全量面板不是敌人，常驻整行才是：Codex 和 Claude 把全量收进 ?，反而记得住。

04 三类显示策略

以及该选哪一类

六家的取值收敛成三类。DevEco 现在用的是最贵的一类：整行常驻、没有面板、没有自定义。

A · 常驻全量

一排键帽一直在

一次看全、不需要按任何键。代价：每帧占一行、抢一次注意力；键一多就没人读，还顶输入框。

只有 DevEco 现状这么干。

B · 情境化 1–3 键 + ? 全量

默认只说「下一步那个键」

常态按状态只留 1–3 个最有用的键；其余全部收进 ? 面板。既教得到人，又不常驻抢位置。

Claude / Codex / Gemini / Cursor / WorkBuddy 五家的共同做法。

C · 纯状态提示

只在「怎么停」时出现

常态几乎什么都不显示，只在生成中冒出 esc to interrupt。最安静，但新手发现不了 @ / /。

Claude / Gemini 的生成帧，是 B 的退化态。

对 DevEco Code：B 为主，C 兜底

B 是默认。保留 .ai-kbd 键帽（可扫、有边界、像可点目标——这正是输入框提示该有的密度），但把常驻数量从 5 砍到 1–3，状态一变就换内容，全量收进 ? 面板。

C 兜住生成中。生成中只有一件事能做（停），整行只留 Esc 停止生成，已写的保留，延续现状已有的 D5 切换。

A 的唯一理由是「教学成本最低」——但那是第 1 天的事，代价是第 2–300 天每天付。

「哪几个键」定完，还有一层没定：这些键平时展开着，还是 hover 才展开、展开多少——下一节比这个。

05 三个大方向对照

一个决策 · 三套可交互 mockup

04 定的是「哪几个键、几个」；这一节定「信息怎么交出来」——三个大方向横着比：全部上下文、Hover 单个详细、Hover 详细 + 邻居简要。 下面三个 mockup 都能把鼠标放上去试（触控屏上点一下；键盘 Tab 到键帽上也会展开）。

方向一 · 全部上下文常驻全量 常态就展开全部键与说明，hover 不新增信息。

优

优

  • 上下文感强：知道「它在哪、邻居是谁」，像翻页预览
  • 生成中只剩 Esc 且无邻居，强调最强

  • 邻居规则要定：左右相邻，还是同类上 / 下一个
  • 键一多一行放不下：要换行 / 横滚，详情要防溢出
  • 无现成竞品，自创形态，手势与手感要原型验证
  • 实现成本三种里最高：当前 / 邻居 / 淡出三个状态
  • 触控无 hover 时退化成方向二，邻居态白做（先评估触控占比）

选型：方向三为默认，方向二做兜底，方向一只当「教学态」

方向三是折中。常态几乎隐形（≈方向二），hover 一次能看到「当前键 + 邻居」——比方向二多一层上下文，扫读速度接近方向一（hover 两三次就看完五个键）。

方向二兜底。窄屏放不下邻居、触控无 hover、键盘只走 Tab 时，退化成「常态壳 + 单个展开」；生成中等强状态本来就只剩一个 Esc，三种方向在这里等价。

方向一不该常驻，但可以「一次性」。首次进入输入框时主动展开一次整行（3 秒后收回）——把方向一的信息量当教学动画用，而不是常驻状态。

06 落到 DevEco Code

八条规则 + 状态表 + 现场对照

不改 .ai-kbd 键帽、不动 .ai-field__bar 右侧的模型 / 上下文 / 发送，只改「哪几个键、什么时候出现、怎么展开」。

  1. 砍数量：任何状态 ≤ 3 个键。现状 5 键整行拆成「有字 / 空输入 / 生成中 / 在等你」四套，见下方状态表。砍掉的 @ / ↑ 全部收进 ? 全量面板。
  2. 状态切换，内容换、高度不换。键帽行固定 min-height:18px 单行、不折行、不推输入框；换状态只换文字与键帽，不换位置。
  3. 空输入教发现，有字教动作。空输入框时是探索，放 @ /；一旦有字，探索键退位，换成 Enter发送 / ShiftEnter换行——键帽永远回答当前状态下「最可能做的那件事」。
  4. 生成中只留停。整行换成 Esc 停止生成，已写的保留，与状态机「中断」一致；右侧发送键同帧变停止。
  5. ? 打开全量面板。把场景九的八条收进 ? 面板，按「输入 / 导航 / 全局」分组；键帽行给一个低调的 ? 入口。
  6. 默认走方向三：hover 详细 + 邻居简要。常态只留壳；hover / 焦点落到某个键，当前键给完整说明，上一个 / 下一个给简要，其余淡出。窄屏或触控无 hover 时退化成方向二（单个详细）。
  7. 触控 / 键盘给等价入口。触控屏点一下即展开（再点收起）；键盘 Tab 到键帽用 :focus-visible 触发同一个展开，不靠 hover 才能看到说明。
  8. 平台化键名 + 关闭开关。mac 用 ⌘⌥⇧⌃ 符号，Windows / 鸿蒙电脑用 ctrl shift alt 文字；设置里可隐藏整行（Enter / Esc 行为不变，只是不显示）。

07 可抄与别抄

从哪家抄什么

可抄 五条

  • 常态只留 ? 一个纯文本入口，全量进面板——抄 Codex / Claude / Gemini 的 D2 + D6 组合。
  • 生成中只留 Esc 一件事，且位置不动——五家全这么做，DevEco 现状已经做对。
  • 行高恒定（Gemini STATUS_MIN_HEIGHT=1 的 GUI 版）：没状态也占一行空位，内容随便换。
  • 状态分「探索 / 动作 / 退出 / 决策」四类，每类一套键——这是 Cursor / WorkBuddy 的 composer 底部行的隐含逻辑，DevEco 的输入框状态机正好接得上。
  • 平台化键名、可自定义、可关闭——Codex 的 ⌃⇧⌥⌘ 与 /keymap、WorkBuddy 的 /keybindings。

别抄 两条

  • 别把整行 5 键当「教学成本低」继续留着。教学只在第 1 天发生；成本是之后每天的一行。要教学，空输入态那三个键已经够了。
  • 别把键帽塞进 .ai-field__bar、和模型 / 上下文 / 发送挤同一行。那行右侧是操作目标（发送键），键帽是提示；混在一起会让「可点的」和「可读的」互相干扰，窄屏还会挤掉发送键。

08 验收条件

七条，可勾

写成能被测的句子。AC-1 与 AC-2 可以直接变成自动化断言，第 5 节那块现场对照就是最小实现。

  • AC-1 输入框任意状态切换，键帽行的 getBoundingClientRect().top（相对输入框底）位移 = 0，行高恒为 18px 覆盖 D1 / D5。空输入、有字、生成中、在等你四态各量一次；允许 1px 亚像素误差。
  • AC-2 任一状态下，可见键帽 ≤ 3 个；其余快捷键只能在 ? 面板里出现 覆盖 D2 / D3。DOM 断言：.x-kbd-note > span 数量 ≤ 3。
  • AC-3 空输入显示 @ /；输入非空后同帧换成 Enter / ShiftEnter 覆盖「探索 / 动作」分工。输入事件后下一次渲染即完成，不许晚一拍。
  • AC-4 生成中，键帽行只有 Esc 停止；右侧发送键同帧变停止，且停止目标（键帽行 + 发送键）bounding rect 不变 覆盖 D5 + 生成态。移动的点击目标 = 点空；同时是可达性要求。
  • AC-5 ? 面板包含场景九全部八条，按「输入 / 导航 / 全局」分组，面板本身可键盘关闭（再按 ? 或 Esc） 覆盖 D6。全量从常驻区挪进面板，但一条都不能丢。
  • AC-6 设置里可隐藏整行；隐藏后 Enter / ShiftEnter / Esc 行为不变 覆盖 D6 自定义。隐藏的是提示，不是快捷键本身。
  • AC-7 hover / 焦点展开（方向二或三）不改变常态键帽行的位置与高度；触控点按与键盘 Tab 有等价展开 覆盖披露方式。断言：常态与展开态下 .x-kbd-note 的 bounding rect 相同；:hover 与 :focus-visible 触发的 DOM 状态一致。
