会话基本单元怎么显示：Codex、Claude、DeepSeek、WorkBuddy、Cursor 对照

AI 编码 / 办公 Agent 的一轮回复由几类基本单元拼成：思考、读与搜、执行命令、改文件、子 Agent、计划、产物、状态计时。这份报告逐个产品看三件事：每类单元在生成中长什么样，生成后变成什么样，默认是否折叠、怎么展开。最后落到 DevEco 智能体对话流的默认策略建议。

资料截至 2026-10-19，来源是官方文档、更新日志、源码与 GitHub / 论坛讨论；没有逐个产品实机截图。每条事实后标注来源性质： 官方 官方文档 / 更新日志 / 源码 社区 GitHub issue、论坛、媒体 推断 据公开截图或使用经验整理、未找到文字出处 待确认 公开资料没写，需实机确认。 各产品卡里的「生成中 / 生成后」示意图是按这些资料复原的低保真，不是截图。

结论单元定义折叠光谱总表 CodexClaudeDeepSeekWorkBuddyCursor 用户反弹对 DevEco 的建议来源
主流做法：生成中透明，生成后收起Codex、Claude Code、Cursor、WorkBuddy 都是运行时显示「正在做什么 + 计时」，单元结束后压成一行摘要（Explored、Ran、Worked for…），点开看细节。
DeepSeek 是唯一把思考原文摊开的网页端开启深度思考后，推理全文排在答案之前、不折叠；其余产品要么只给摘要（Claude、Codex），要么默认收起（Cursor）。
折叠有三个粒度，越往上越省屏、越难盯单元级（命令输出只留头尾）→ 组级（Ran N commands、Called slack 3 times）→ 回合级（Cursor 把整轮收进 Worked for…）。
收太狠会被用户顶回来Codex 0.149 把成功命令合并成 Ran N commands，被用户反对后宣布在 0.153 回滚；Cursor 3.14 的回合折叠至今被抱怨。用户要的是能盯住正在跑的命令。
展开太多也会被抱怨Claude 桌面端生成中把思考全文展开，用户嫌长、找不到答案，而且重启后又变成收起，状态不一致。
全量细节都挪进「另一个视图」Codex 的 Ctrl+T 转录、Claude Code 的 Ctrl+O 转录与 Focus view、DeepSeek Harness 的 Trajectory 页签、WorkBuddy 的右侧产物 / 后台任务面板。主对话流只留摘要。

会话基本单元本报告对照的八类

不同产品叫法不同，这里统一成八类，后文总表和产品卡都按这个口径。

思考 / 推理模型在回答前的推理；有的给原文，有的给摘要，有的只给计时。
读与搜读文件、列目录、grep、联网搜索；量大但单条信息少，最常被合并。
执行命令Shell / Bash、测试、构建；有输出、有退出码、可能长时间运行。
改文件编辑、新增、删除；带 diff，常需要审阅或授权。
子 Agent / 并行任务派生的子任务，有自己的工具调用与状态。
计划 / 待办Agent 自己拆的步骤清单，带进行中 / 完成状态。
产物交付的文件、文档、网页；常在侧栏预览。
状态与计时运行中的指示器、已用时间、中断入口、本轮耗时。

用户反弹折叠多少，用户的意见并不一致

Codex：命令被合并后没法盯着跑合并成「Ran N commands」后，用户说实时监督能力明显变差、没法中途纠偏，转录视图「就是一堵文字墙」。官方宣布回滚，并提出改进转录模式。另有用户提议三档设置：Compact / Commands & edits / Fully expanded。
Cursor：回合折叠藏掉了正在审的 diff用户反映发下一条消息后上一轮的 diff 被收起，滚动和审阅都被打断，还有人说折叠后模型找不到前面的方案。官方坚持这是有意设计，但承认没有关闭开关。
Claude 桌面端：思考太长，又关不掉反方向的抱怨：生成中思考整段展开，挤掉答案；重启后又变成收起，状态不一致；设置里没有开关。同期也有多个 issue 要求「始终显示思考」。

共同点：用户反对的不是折叠本身，而是不可控和不一致。想盯过程的人要看到正在跑的命令和改的文件，想看结果的人要答案不被推下去，两类人都要一个能记住的开关。

对 DevEco 智能体对话流的建议默认值 + 可调

以下是基于上面对照的设计建议，不是任何一家的现成做法。

单元生成中生成后默认依据
思考一行滚动摘要 + 计时，可点开看全文；不默认铺开全文折叠 收成「已思考 N 秒」，点开看全文DeepSeek 全展开有人专门装脚本折叠；Claude 桌面端展开被抱怨；Claude.ai / Codex CLI 的计时 + 摘要标题最省屏
读与搜组级一行「正在查看 · 当前文件名」，逐条追加折叠 「查看了 N 个文件，搜索 M 次」，点开列出文件名Codex Explored 分组；信息密度低、可安全合并
执行命令执行前就显示命令本身，输出实时滚动，带中断与转后台部分 命令始终可见，输出只留头尾几行；失败的默认展开Codex 合并命令被回滚；Claude Code 执行前显示命令被当正面例子；Codex 按退出码上色
改文件文件名 + 增删行数实时更新部分 文件名和行数可见，diff 点开；不和其他单元合并成无法展开的一行Codex App「Edited N files」不可展开、Cursor 回合折叠收掉 diff，都被抱怨
子 Agent每个子 Agent 一行：状态、耗时、当前步骤折叠 一行结果摘要，点开看它的工具调用Claude Code agent map；WorkBuddy 并行思考曾互相覆盖
计划 / 待办常驻状态区，实时打勾保留最后一版，且在任何密度下都可见Claude Code Focus view 仍保留最新待办
产物生成即出现在对话流，联动侧栏预览产物卡片 + 侧栏标签页WorkBuddy present_files 与右侧面板
状态与计时「已处理 X 秒 · Esc 中断」本轮总耗时，挂在回合末尾Codex 状态行、WorkBuddy 每轮运行时间、Cursor Worked for
  1. 三档密度，一处设置、全局记住。简洁（只留回答、待办、产物）/ 标准（上表默认）/ 详细（全部展开）。对应 Claude Code 转录三档和 Codex 用户提的三档，解决「不可控」。
  2. 回合级折叠不要自动发生。Cursor 的回合折叠是本次对照里反对声最集中的设计；如果要做，只折叠已审阅过 diff 的回合，并且可关。
  3. 同一份数据，生成中、生成后、重开会话三种状态显示一致。Claude 桌面端「生成中展开、重启后收起」和 WorkBuddy 5.4.5 补齐离开期间内容，说明重开会话的还原是单独要设计的状态。
  4. 全量过程放独立的时间线视图。参照 DeepSeek Harness 的 Trajectory 与 Codex / Claude Code 的转录：对话流只留摘要，耗时、token、嵌套调用去时间线看。可与已有的「AI 时间线」方向合并考虑。
