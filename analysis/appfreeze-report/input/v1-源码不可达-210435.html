根本原因

用户在 FreezeNoteDetailPage 页面点击 Save 按钮触发 onSaveClick，其调用的 NoteRepository.saveNote(sync=true) 在主线程同步执行 saveNoteSync 9 步保存流水线（写库 → 搜索索引 → 附件引用 → 标签关联 → 分类归属 → 缩略图元数据 → 云同步排队 → 偏好清理），每步约 0.5s，单轮约 4.0s。第一轮保存执行期间（11:15:03.418）用户因界面无响应再次点击，第二个 MMITask 被排队至 11:15:06.639 分发，第二轮流水线紧接执行。主线程连续约 8s 满负荷解释执行 ArkTS 字节码（两次抓栈 state=R、CPU 占用约 98%、栈顶分别为循环判定与属性访问指令），EventHandler 队列无法处理任何后续任务（堆积 62→115，vSync 与输入均被阻塞），最终于 11:15:07 触发 THREAD_BLOCK_3S 告警、11:15:10:313 触发 THREAD_BLOCK_6S 冻屏上报。

  • 责任领域：应用
  • 定界依据：阻塞主线程的执行流为应用自有 ArkTS 代码——应用域日志 A00000/FreezeNoteDetail、A00000/NoteRepository 按步推进，栈顶为 ArkTS 字节码解释器桩（解释执行的是应用页面代码）；整机资源正常（CPU 28%、可用内存 2611MB、热等级 0）；系统侧 binder/FFRT/GC 线程全部空闲，无 IPC 阻塞与锁竞争；saveNote(sync=true) 的同步执行方式由应用自身选择。

// FreezeNoteDetailPage 的保存按钮回调：只调度，不同步执行

修复说明：冻屏的直接原因是保存流水线（单轮约 4.0s 的同步计算）在主线程 MMITask 回调内执行。移入 TaskPool 后主线程事件循环（MMITask、vSyncTask 分发）保持响应，队列不再堆积。

建议2: 保存操作增加进行中（in-flight）守卫，防止重复点击叠加执行

private saving = false

async onSaveClick() {
  if (this.saving) return // 保存进行中，忽略重复点击
  this.saving = true
  this.saveButtonEnabled = false // 立即禁用按钮，给用户即时反馈
  try {
    const result = await taskpool.execute(saveNotePipeline, this.noteId, this.buildPayload())
    this.onSaveFinished(result)
  } finally {
    this.saving = false
    this.saveButtonEnabled = true
  }
}

修复说明：本日志显示用户在第一轮保存执行期间（11:15:03.418）再次点击，第二轮约 4s 的流水线紧接执行，把无响应时长拉长至约 8s 并触发 6S 上报。in-flight 守卫与按钮禁用消除重复触发叠加，同时避免同一笔记的并发写。
