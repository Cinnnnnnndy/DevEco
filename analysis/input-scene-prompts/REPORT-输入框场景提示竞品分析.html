输入框上方的场景提示：豆包、WorkBuddy 有，Codex、Claude Code 为什么没有

豆包、WorkBuddy 在输入框上方放一排场景按钮，点进去还会给参数和示例提示词；Codex、Claude Code 这类编码工具没有。本页把各产品按网页、桌面、手机、IDE 插件、终端逐端拆开对照，解释编码工具不放按钮的原因，再按 DevEco 的用户判断要不要做、做成什么样。

01结论

  1. 编码工具不是没有场景提示，而是换了形态。它们不用豆包那种「固定按钮 + 场景内表单」，改成两种：一是从上下文生成的建议，比如 Claude Code 的灰字示例取自本仓库 git 历史，Xcode 的动作跟着选中的代码出现；二是用户自己沉淀的快捷方式，比如 / 命令、Codex 的编号预设、Android Studio 的提示词库。
  2. 决定有没有入口的，是用户这一刻在做什么，跟用哪台设备无关。同一个 App 里，对话有入口，写代码没有：Claude 手机 App 的对话页和 Code 页签是这样，ChatGPT 手机 App 的对话和 Codex 也是这样，WorkBuddy 也把新建任务分成 Work 和 Coding 两种模式。来聊天的人常常在想「它能帮我做什么」，来写代码的人手里已经拿着报错或需求单。
  3. 豆包的场景按钮其实是模式切换。写作、图像、视频、PPT 背后是不同的模型、工具和参数，不先选模式就给不出对应的参数面板。编码工具只有一种能力，用什么工具由模型自己挑，加按钮等于让用户替模型做一次判断。
  4. 编码工具试过、也撤过。Codex CLI 删掉了占位符里轮播的示例句，理由是用户觉得困惑；Codex 网页去掉了 Ask 按钮，用户抱怨失去了先拆任务再动手的入口。两边现在都在做回答后的下一句推荐，而且先上了桌面端。
  5. DevEco 不建议照搬常驻按钮，但比 Codex、Claude Code 更需要场景引导。签名证书、上架预检、Android 迁移、一多适配这类任务做得少、门槛高，而最大的两类用户（学习者和迁移开发者）恰好不知道该怎么问。建议做三件事：新会话的空态显示按工程状态生成的场景卡；在问题发生的地方放入口；场景沉淀成团队共享的 / 命令。
  6. DevEco 的直接竞品已经这么做了。Android Studio 把 Gemini 入口放在新建工程向导、构建输出、Logcat、版本目录文件、Compose 预览里，场景提示词集合放在官网的提示词库页面，按 Compose、大屏、Wear、TV、车机等分类；Xcode 在报错弹窗里放「Generate fix」，选中代码有 Coding Tools。两家都没有在对话框上方放场景按钮。

05编码工具为什么不放场景按钮

厂商没有公开说明过这个取舍。以下六条是从体验角度做的推断推断，每条附可以观察到的现象。

1. 用户进来时已经带着任务

大众助手要解决「空白页」：打开了，但不知道能让它干什么，按钮就是功能目录。开发者打开编码工具，多半手上有报错、需求单或 review 意见，缺的是执行。

现象：同一个 App 里，对话页有入口，Code 页签没有。

2. 上下文本身就是提示词

在仓库里，当前文件、选区、报错、git 改动已经说明了用户想做什么。对所有人都一样的按钮，信息量不如这些。

现象：Claude Code 从 git 历史取示例，Xcode 跟着选区，Copilot 和 Codex IDE 插件带入打开的文件。

3. 只有一种能力，没有模式要切

豆包的写作、图像、视频背后是不同的模型和参数面板，按钮是在切模式。编码 Agent 读文件、跑命令、改代码由模型自己选工具，硬加一层模式等于让用户替模型做路由。

现象：Codex 网页去掉了 Ask / Code 的模式选择。

4. 编码任务是长尾

写作和图像能归成十来类；编码任务跟项目、语言、框架强相关，几个固定按钮覆盖不了，覆盖到的往往是最不需要按钮的任务。对天天用的人是噪音，还挤占侧栏空间。

现象：Codex CLI 删掉轮播示例句，理由是用户觉得困惑。

5. 专家习惯自己定义、用键盘召唤

开发者愿意为高频流程写一条自定义命令。编码工具把「场景」交给用户：/ 命令、Skills、预设、提示词库，可以放进仓库共享。

现象：Codex 编号预设、Android Studio 项目级提示词库、Claude Code 自定义命令。

6. 衡量目标不同

大众助手靠按钮把用户导向新功能，看渗透和留存；编码工具看任务做没做成、改动有没有被接受，界面越少打扰越好。

现象：WorkBuddy 更新日志里大量是首页推荐、技能推荐、闲置提醒这类运营动作。
手机端也一样。手机打字最费劲，按理最需要按钮，但 Claude Code 和 Codex 的手机端都没加，而是让人少打字：接着电脑上的会话做，用 /goal 定长期目标，把手机当成派活、看进度、审批的地方。

06DevEco 的用户要什么

按《DevEco 生态位与体验舆情》§06 的人群拆分。DevEco 和 Codex、Claude Code 最大的不同是，鸿蒙有一批平台特有、低频、门槛高、步骤固定的任务：开发者不常做，不知道 Agent 能做，也说不清怎么描述。场景引导主要在这些任务上有用。

人群来时有没有任务最可能卡在哪适合的形态
学习者 / 转行者数百万人次 / 年常常没有，跟着教程走不会描述需求；「缺学习资源 / 文档」是第二大顾虑（36.4%）A空态场景卡、示例；B下一步推荐
Android / 跨平台迁移存量 App 迁移主力有，但用 Android / iOS 的说法不知道鸿蒙里叫什么、怎么做：权限、生命周期、一多断点、签名A迁移场景的槽位；B检测到 Android 工程时出现入口
企业团队头部应用与大部分使用时长有，团队内高度一致CI、规范检查，同一套话每人都要写一遍C项目级命令和 Skill，随工程共享
独立开发者舆情最响的一群有，集中在上架前后审核被打回、证书过期、权限说明B在构建失败、签名报错、预检结果旁放入口

07DevEco 的竞品怎么做场景引导

DevEco 的直接对手是平台 IDE：Android Studio 和 Xcode。上一节说的那批低频、门槛高的平台任务，它们都有对应的入口。下表按 DevEco 的任务逐条对照。

DevEco 的任务Android Studio（Gemini）Xcode形态
新建工程学习者起步新建工程对话框里，模板卡片旁边有「Create with AI」：写一句需求（可附草图），先出计划给人改，再自动生成、构建、修错，直到能编过。官方未找到对应A放在低频的起步时刻，长在原有向导里
构建失败构建输出里的「Ask Gemini」链接，诊断并修复构建和同步错误。官方报错弹窗底部的「Generate」按钮，交给助手修。官方B入口长在报错旁
崩溃 / 冻屏分析Logcat 里出现异常时点「Ask Gemini」；App Quality Insights 给崩溃摘要和下一步，附示例代码和文档。官方未查B入口长在日志和崩溃报告旁
Android 迁移 / 版本升级Refactor 菜单「Update Dependencies」，或在 libs.versions.toml 的版本号上点「Update all libraries with Gemini」；先出可勾选的计划清单，执行时自己修构建错误、跑测试，最后给报告，可逐文件看 diff、回滚。AGP 用升级助手。官方未查B入口在文件上；流程是计划、执行、报告
上架预检Play Policy Insights：Code 菜单手动检查，结果进 Problems 窗口和 lint 警告，也能接进 CI；没有自动修复，只给政策说明和链接。官方未查检查项本身不是 AI，结果出现在问题列表里
一多 / 大屏适配在 Compose 预览面板里用一句话改 UI；为组件生成预览和假数据；按参考图改界面。官方Coding Tools 可生成预览。官方B入口在预览面板
场景提示词集合官网提示词库页面，按 Kotlin、Compose、无障碍、Play 结算、性能、Flutter、大屏、TV、Wear、车机分类；IDE 内用提示词库保存，支持项目级共享。官方未找到对应A放在文档站；C放在 IDE 里
选中代码编辑器右键 Gemini 菜单，调用提示词库。官方Coding Tools：解释、写文档、生成预览和 Playground、改写。官方B跟着选区
  • 场景引导做在任务发生的地方。Android Studio 有八九个 Gemini 入口，分别放在新建向导、构建输出、Logcat、版本目录、预览面板、右键菜单里，没有一个放在对话框上方。DevEco 的签名报错、冻屏报告、预览器、构建输出都有对应位置。
  • 唯一类似豆包的固定入口，放在「新建工程」这个低频时刻。Android Studio 把「Create with AI」和模板卡片并排，给学习者一个起点，但不常驻在每次对话里。DevEco 的新建工程向导可以照这个做。
  • 重任务走「计划、执行、报告」。依赖升级先给可勾选的计划，执行中自己修错，最后给报告、可逐文件回滚。Android 迁移、一多适配这类改动大的场景，进入后应当先出计划，而不是直接动手。
  • 场景目录放在文档站，按设备形态分类。Android 的提示词库按大屏、Wear、TV、车机分类，正好对应鸿蒙的一多。DevEco 可以在开发者文档里做一份按设备和任务分类的提示词库，一键存进 IDE。
  • 检查类任务先做成确定性检查，再接 Agent。Play Policy Insights 本身是 lint，不靠 AI；DevEco 的上架预检也可以先出检查结果，再在每条结果旁放「让 Agent 处理」。

08对 DevEco 的建议

不放常驻按钮。只在三个时机给引导：新会话还没输入时、问题刚发生时、一轮回答结束时。

新会话空态按工程状态生成，最多四张

  1. 空态场景卡按工程状态生成。来源是工程类型、上次构建结果、签名和断点配置、日志里有没有冻屏，不是厂商写死的列表。没有信号时给新手三张：解释这个工程、生成一个页面、跑到模拟器上。依据：Claude Code 从 git 历史取示例，Codex 删掉了不相关的轮播示例。另外在新建工程向导里放「用 AI 创建」，参照 Android Studio 的 Create with AI。
  2. 场景卡就是 / 命令的可视化入口。点卡片等于在输入框里填好命令和参数，用户看得到、改得了，下次可以直接打字。依据：Codex 编号预设、Copilot 提示词文件。
  3. 进入场景后给槽位，并说明会用到哪些能力。迁移选模块和目标设备，一多选断点，上架预检选签名配置；列出会调用的鸿蒙工具；迁移、一多这类大改动先出可勾选的计划，结束给报告、可回滚。依据：豆包第二层的参数、Android Studio 的 $SELECTION 和依赖升级流程。
  4. 入口放在问题发生的地方。构建失败、签名报错、冻屏报告、Profiler 卡顿帧旁放「让 Agent 处理」，带着现场信息进对话；上架预检先出确定性检查结果，再逐条接 Agent。依据：Android Studio 构建输出和 Logcat 的「Ask Gemini」、Xcode 报错弹窗的「Generate」、Play Policy Insights。
  5. 回答后推荐下一步，接受方式看得见。一条、可换、旁边标出 Tab。依据：Claude Code、Codex 桌面 App、WorkBuddy 5.8.0；claude-code#76591 的反馈。
  6. 团队可以沉淀自己的场景。项目级命令和 Skill 存在工程目录里随版本库共享，团队的「上架前检查」会出现在每个人的空态里。依据：Android Studio 项目级提示词库和官网提示词库、WorkBuddy 企业自定义推荐问题。开发者文档里按设备形态和任务分类做一份提示词库，可一键存进 IDE。
  7. 分端落地。DevEco Studio 面板做空态场景卡和情境入口；DevEco Code 终端只给一条按工程状态生成的灰字示例，不轮播；以后如果在手机或鸿蒙电脑上远程看 Agent，参照 Claude Code 和 Codex 的手机端，做派活、看进度、审批和通知，不放场景按钮。
输入框本身的九个状态见 DevEco 智能 · 视觉与交互 → 输入框，空态卡和槽位输入落地时需要和那一章的状态机对齐。

09待验证

  • 实机截图：豆包三端的技能名称和第二层参数；Claude 手机 App 对话页空态；github.com 与 GitHub Mobile 的 Copilot 空态；CodeGenie 侧栏空态。总表里标「待确认」的格子都要补。
  • 空白输入的比例：统计 DevEco Code 和 CodeGenie 新会话第一条消息的长度、类型和发出前的停留时长。停留长、首条短的比例高，说明空态引导有需求。
  • 低频任务的求助量：签名证书、上架预检、迁移、一多适配在论坛和工单中的占比，用来定首批场景卡。
  • A / B：空态场景卡对学习者和迁移开发者首轮任务完成率的影响，以及对熟练用户发送速度的影响。
