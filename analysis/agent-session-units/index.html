会话基本单元怎么显示

返回研究分类 启动页

把一次 Agent 会话拆成看得见的单元：思考、工具调用、工具结果、计划、收尾。 这一页只答四件事：每个单元默认长什么样、是否默认折叠、生成中与生成后差在哪、展开入口有几个。 对象是 Codex、Claude Code、DeepSeek Harness、WorkBuddy——四种形态：终端、终端、Web/桌面、桌面工作台。

没有一家默认展开过程 四家都把工具调用压成一行；差别只在「一行里放什么」和「折叠发生在哪一层」。
思考是「另一个视图」，不是「一个折叠块」 Codex 完成后直接不进普通流；Claude 把正文关在 transcript 里；DeepSeek 只给首行摘要。
折叠的时机也是一条设计 完成即折、下一句才折、永不折只切视图——三种都能成立，混着用才会让人找不到刚才那一步。

01 先定义「会话基本单元」

七个单元

「思考怎么显示」不是一个组件问题，而是「一次会话被切成哪些块、每块默认给多少」的问题。 先把单元列齐，四家的差异才有地方放。

单元它回答什么默认该给多少四家的处理
U1 你的输入 我让它做什么 全文，不折 四家都是完整气泡或引用行；折叠会让上下文断掉。
U2 思考 它有没有理解对、在往哪想 一行状态；正文按需 Codex 完成后不显示；Claude 只留一句；DeepSeek 留首行；WorkBuddy 没有这个单元。
U3 计划 / 待办 总共几件事、做到第几件 一张卡，可收起 WorkBuddy 放在最显眼处；DeepSeek 并进过程组；Codex、Claude 有 todo 但不当主单元。
U4 工具调用 它做了什么 一行：动词 + 对象 四家一致。差别只在行尾放什么：耗时、diff 统计、退出码。
U5 工具结果 做成了没有、证据是什么 一行摘要；正文按需 Codex 预览 3 行；Claude 1 行；DeepSeek 展开成卡；WorkBuddy 展开 diff。
U6 提问 / 审批 哪里要你拍板 不折 四家都不折。这是唯一「默认必须打断」的单元。
U7 收尾 这一轮花了多久、产出什么 一行 Codex 有 Worked for 12s；DeepSeek 整轮一行「用时」；WorkBuddy 任务卡 4/4；Claude 在底部状态位

判断「是否默认折叠」，要分三个问题问

  • 位置：折的是单个单元（U2 / U4 / U5），还是一段过程（U3 + U4 + U5 打包），还是整轮？
  • 时机：生成中就折、完成那一刻折、还是下一句输入才折？
  • 入口：行尾箭头、组头、快捷键、设置项——入口越少，越像「不让人看」；入口太多，等于没折。

下面四家的「默认折叠」都写在这三个维度上，不用「折 / 不折」一个词概括。

先给结论

Codex 最激进：思考不是「折叠」，是「完成后不存在于普通视图」。 Claude 分两层：对话层只留结论与每步一行，证据层（transcript）另开一个视图。 DeepSeek 把折叠做成策略：同一份会话有四档密度、两种折叠时机，用户调的是「给我看多少过程」。 WorkBuddy 换了主单元：不模拟「模型想了什么」，只给「要做几件事、做到第几件、产出了什么」。

03 Codex CLI

思考用另一个视图承载

终端形态的极限做法：对话流只留「我让它做什么」和「它做了什么」，思考只活在生成中的状态行里。 完成后要看思考，得主动开 Ctrl+T。

生成中
你修一下这个失败用例
•Runningpnpm test -- src/list
Thinking · reading the failing test firstesc
生成后
你修一下这个失败用例
•Ranpnpm test -- src/list
└ 3 failed · 12 passed
•Ranrg -n "cachedCount" src
└ src/ListPage.ets:42
Worked for 1m 12s · 10:24
机制与证据
  • 思考完成后不进普通视图。记录思考块的字段是 transcript_only: true，意思只在展开的 transcript 里保留已完成的思考块。源码
  • 生成中只有一行。状态头取最新一行思考摘要（latest_summary_line），渲染在底部状态区，不写进对话记录。源码
  • 工具预览固定 3 行。DETAIL_PREVIEW_LINES = 3；没输出时补一行 └ (no output)；失败改成 Exited (status N)。源码
  • 整轮有一行收尾。Worked for 1m 12s · 10:24，dim，属于 FinalMessageSeparator。源码
  • 入口是快捷键，不是箭头。Ctrl+T 打开 transcript overlay，F4 聚焦活动组看细节，Alt+R 切原文。源码
一句话：默认答案是「不需要看思考」。它把「过程」当噪音，只在你要审计时整屏给出。

04 Claude Code

对话层与证据层，两个密度

和 Codex 一样不铺思考正文，但它把「完整过程」做成一个可切换的视图，而不是只藏在快捷键后面： 对话层是检查点，transcript 层是全量。

●Read(src/ListPage.ets)
└ Reading 214 lines… (ctrl+o to expand)
Thinking…esc
生成后
>修一下这个失败用例
●Read(src/ListPage.ets)
└ Read 214 lines

└ Updated 1 file
●Bash(pnpm test -- src/list)
└ 12 passed (ctrl+o to expand)

机制与证据
  • 思考正文默认关。设置项 showThinkingSummaries 的说明是「Show thinking summaries in the transcript view (ctrl+o). Default: false.」源码
  • 生成中只给状态。✻ Thinking…（dim + italic），结束后同一处变 thought for Ns；这段文本属于底部 spinner，不进对话流，也不留成可展开的单元。源码
  • 每步一行 + 一行结果。工具头 ● Tool(args)，下一行 └ …；长结果写 (ctrl+o to expand)，读文件写 Read output (… to expand)。源码
  • 两种默认视图。设置项 defaultView：chat（SendUserMessage 检查点）或 transcript（完整）；Ctrl+O 切。源码
  • brief 模式更狠。开启后模型只能通过 SendUserMessage 说话，「text outside it is hidden from their view」；入口 Ctrl+Shift+B。源码
一句话：把「折叠」升级成「两个密度」——同一段会话，结论层与证据层各自完整，不靠每行一个箭头。

05 DeepSeek Harness

折叠被做成一套策略

四家里把「给你看多少过程」说得最明白的一家：单元行固定 24px，过程成组， 生成中平铺，完成后整轮折成一行「用时」；密度与折叠时机都做成设置。

生成中
▾正在运行命令pnpm test -- src/list
▸编辑src/ListPage.ets+3 −1›
▸运行pnpm test -- src/list
✳Think先看失败用例，再改缓存判断…›
生成后 · 默认
›用时 1m 12s3 步
改好了：缓存判断改成按 key 比较，测试已过。
展开 → 组头「已读取文件…」→ 24px 行 → 卡
机制与证据
  • 单元行固定 24px。工具行与思考行都是 height: 24px，摘要单行省略；图标 16 + 标题 + 2×2 点 + 摘要。源码
  • 思考生成中显示「最新完成段落的首行」。摘要单行 + 右侧 mask-image 渐隐；完成后按 settledReasoningPreview 决定留不留首行。源码
  • 生成后有两层入口。整轮先折成一行「用时 1m 12s ⌄」（TurnProcessNodeView）；展开后是组头「已读取文件、执行了命令并修改了文件」，再展开才是 24px 的行。源码
  • 过程组有一句汇总。生成中是「正在读取文件 / 正在运行命令」；收起后由计数拼成「已读取文件、执行了命令并修改了文件」，超过三类用「等」。源码
  • 四档密度 × 两种时机。compact / standard / detailed / verbose；折叠时机 completion 或 next-input；默认 detailed：生成中平铺，完成后整轮折成一行「用时」（foldCompletedTurns），展开该行才见到组头。源码
  • 展开体有上限。终端卡输出 224px 内滚，diff / read / 搜索结果各有行数上限，不把会话顶走。源码
一句话：用户调的不是「这个块展开」，而是「给我看多少过程」；单个块只保留一个 24px 的身份。

06 WorkBuddy

计划是主单元

面向办公角色的桌面工作台，不模拟「模型怎么想」，而是把「要做几件事、做到第几件」放在最上面。 会话流里正文与动作交错，动作行仍然是一行。

  • 计划卡在对话流最上面。官方截图里两次出现：完成态的「任务列表 4/4」与之后的「进度更新 4/4」；每项带状态圈 / 勾。截图

  • 中间步骤可展开。官方文档原句：「执行中的阶段说明」「可展开查看的中间步骤」；对话区顶部可开右侧详情面板。文档

07 折叠发生在三层

位置 · 时机 · 入口

四家看起来完全不同，其实都在三个高度上做选择。把这三层分开看，就不会把「思考默认不显示」 和「过程组默认收起」混成同一个决定。

L1 · 单元
思考 24px
工具 24px
结果 24px

折正文，不折身份。四家都有这一层。

L2 · 步骤组
已读取文件、执行了命令…
组内仍是 L1 的行

折一段连续过程。DeepSeek 有（组头 + 行）；WorkBuddy 在计划项下挂步骤；Codex / Claude 不打包。

L3 · 整轮
这一轮的过程整体收起
结论与证据留下

折「这一轮怎么做的」。DeepSeek 折成一行「用时」；Codex 用另一个视图，Claude 用另一个密度。

时机比位置更容易做错

同样是 L2 折叠，完成即折会在结论刚出现时把过程抽走，人还在对照；下一句才折把「刚才那几步」 留到用户开始下一个问题，代价是会话更长。DeepSeek 把这两个都做成设置（completion / next-input）， 说明它认为这不是风格问题，而是使用场景问题。

08 共识与真分歧

五条共识 · 四个分歧

把四家放在一起，能抄的其实只有共识；分歧部分没有对错，取决于用户在这段会话里要「验收」还是「围观」。

共识四家怎么做为什么成立
C1 一屏只有一处「活着」 Codex 底部状态行、Claude 的 ✻ 行、DeepSeek 组头 shimmer、WorkBuddy 进度卡 动效用来回答「还在跑吗」，多了就变成噪音。
C2 工具先给一行 没有一家默认铺开命令输出；最长的是 Codex 的 3 行预览 人先判断「做的对不对」，再决定要不要看细节。
C3 思考正文默认不给 Codex 完成后不显示；Claude 默认关；DeepSeek 只留首行；WorkBuddy 没有这个单元 思考是审计材料，不是交付物。
C4 降噪靠层级，不靠删除 另一个视图 / 另一个密度 / 组头 / 卡片，原文都还在 出事时要能回到原话；删掉就不可逆。
C5 失败与等待不折 Codex Exited (status N)、DeepSeek 错误 / 中断保留摘要、Claude 保留错误行 这是唯一必须打断的单元，折叠等于藏事故。

四个真分歧

  • D1 思考给不给首行。Codex / Claude 不给，DeepSeek 给（可关）。给首行能让人早一点发现「理解错了」，代价是每轮多一行灰字。
  • D2 折在单元还是组。Codex / Claude 让每一步独立成行；DeepSeek 先用一句汇总盖住一组。前者便于抽查某一步，后者便于跳读一整轮。
  • D3 什么时候折。完成即折（Codex 的思考、DeepSeek 默认）对「看结论」友好；下一句才折（DeepSeek 可配、WorkBuddy 的进度卡）对「边看边核」友好。
  • D4 一行里放什么。Codex 放「命令 + 末 3 行」，Claude 放「工具名 + 结果摘要」，DeepSeek / WorkBuddy 放「动词 + 对象 + diff 统计」。放结果量能直接判断影响面，放结果摘要能直接判断成败。

可点的对照：同一段过程，三种密度

按 DeepSeek 的四档密度简化成三档。切换看「同一份会话，只是给多给少」——不是三家产品的截图。

收起 = 只留组头与结论；标准 = 组头 + 24px 行；展开 = 行下挂证据。

09 落到 DevEco Code

六条可抄 · 两条别抄

不新增组件：现有「过程收成一行」、状态机与 AI 色已经够用。要补的是「行里放什么」与「什么时候折」。

建议怎么做依据落在哪
A 一行一个动作，固定 24px 行内三段：动词 / 对象（可点开文件）/ 结果量（+N −N、耗时、退出码）；摘要单行省略 DeepSeek 工具行 CSS、WorkBuddy 截图 08「过程收成一行」；ai.css 行高
B 思考默认只留一行 生成中一行 shimmer + 最新一句；完成后留「用时」或首行；正文进 transcript Codex / Claude / DeepSeek 三家里两家不给正文 ai.css 进行态；状态机八态
C 最新轮平铺，历史轮成组 生成中平铺；完成后整轮折成一行「用时」，展开后是组头；历史轮同理 DeepSeek 默认 detailed 策略 08 / 31 Agent 工作台
D 折叠时机给两档 「完成即折 / 下一句再折」写进设置；默认完成即折，但同一帧接住高度 DeepSeek 两档；状态页 AC-3 状态锚定 · 验收条件
E 展开体设上限 + 内滚 终端 / diff / 搜索结果各有封顶，展开不把状态行顶走 DeepSeek 224px 终端卡；Cline 150–200px ai.css 面板；终端卡
F 失败 / 在等你 / 被中断不折 这三种状态永远保留摘要与入口，颜色只在此时抢注意力 四家一致 状态机的错误 / 等待态

两条别照搬

别把思考全文默认展开。Codex 与 Claude 都不这么做；DeepSeek 也只给首行。开发者要看的是「改哪、为什么改、验过没有」，不是模型的草稿。

别把计划卡做成主单元。WorkBuddy 的计划卡服务于「我不懂代码，只想看进度」；DevEco 的用户要的是 diff、构建结果、真机证据。计划可以有一行，但不该占掉对话流最上面那块。

一条组合建议（不改组件）

L1 行常驻，L2 组头只在历史轮出现，L3 不折整轮。 生成中把「正在跑」留在面板固定行（不是内容末尾），过程行在内容流里长；完成时把这一轮收成一行「用时 + 一句组头」， 再展开才是过程行；结论、diff 与验证结果始终留在流里。要审计时进 transcript，不在对话流里逐块展开。
