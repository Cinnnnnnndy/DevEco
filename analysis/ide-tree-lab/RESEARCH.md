# IDE 文件树：间距、层级与信息密度

研究整理与方案设计：**钱佳丽**  
日期：2026-10-15  
状态：设计建议，待真实任务验证

## 建议方案

在箭头容器 20px、文件图标容器 20px、文件名字号 16px 的前提下，建议每级缩进 **20px**，图标到名称间距 **4px**，行高 **28px**。窄侧栏与深目录可切换 **16px** 紧凑缩进；24px 留作比较。

| 参数 | 标准 | 紧凑 |
|---|---:|---:|
| 每级缩进 | 20px | 16px |
| 箭头容器 | 20px | 20px |
| 文件图标容器 | 20px | 20px |
| 箭头容器到文件图标 | 4px | 4px |
| 文件图标到名称 | 4px | 4px |
| 文件名字号 | 16px | 16px |
| 行高 | 28px | 28px |
| 左侧起始留白 | 8px | 8px |

缩进用于表达父子关系，图文间距用于绑定图标与名称，两者承担不同任务。20px 的层级变化与图标容器同一量级，便于扫视；16px 能为深层长文件名留出更多空间。文件行仍保留箭头槽，使同级文件与目录的名称对齐。

以根节点深度为 0，名称起点 = 8 + 深度 × 缩进 + 20 + 4 + 20 + 4。深度为 4 时，标准模式名称起点为 136px，紧凑模式为 120px，紧凑模式多保留 16px 名称空间。剩余空间还需扣除右侧留白、滚动条与状态徽标。

## 竞品研究的使用方式

研究覆盖 IntelliJ IDEA、Fleet、Xcode、Cursor、TRAE，综合比较箭头槽、图标、文字、相邻间距与层级缩进。页面中的 IntelliJ / Fleet / Xcode 数值为截图量级估算，包含历史样本；Cursor / TRAE 使用 VS Code 上游布局作参考，不是本品当前版本的精确测量。因此不对五款产品宣称统一的实测结论。

测量时区分图标可见图形与布局容器。当前 IDE 效果页保留 Int UI Kit 原始 16px 图形，在 20px 容器中居中；4px 指容器边缘到文字的布局间距，视觉墨迹间距可能更大。字号、原生 pt、CSS px 和系统缩放也应分别记录。

## 评审与验证

使用相同目录、相同侧栏宽度比较 16 / 20 / 24px，观察定位时间、误点、层级判断与名称截断；覆盖 280 / 320 / 360px 侧栏、深层目录和长文件名。页面结论是待验证的推荐起点，不是用户实验结果。
