OpenBitFun 一层界面：那一页不叫「首页」

智能助理、任务看板、小应用、扩展与兼容现在各占一个导航项。这次的方向是：一层只留做事的入口，配置收进设置，小应用另想启动方式，跟用户个人相关的资源归到一页。这一页该怎么定义，是这里要讨论的事。

2 · 为什么不叫首页

  • 首页的职责是分发：落地、看一眼、再跳去别处。分发的事侧栏和 ⌘K 已经做了，会话和任务都在一层，这一页没有导流的活。
  • 首页暗示「每次打开先到这」：可是用户打开 OpenBitFun 是来说话、来看任务的，先看一页统计是多一步。
  • 这页里的东西有共同点：累计 Token、连续天数、智能体、助理、技能、工具、兼容的应用、设备、模型、记忆——都是属于这个用户、被 Agent 拿来用的东西。它是一本账，不是一个入口。
  • 现有文案已经在这么说：它能调用哪些智能体、它懂什么专项知识、它能用什么工具。主语一直是「它」。

3 · 候选定义

推荐
它 · 本体页

这一页就是 Agent 本身：它是谁（形象、长期助理）、会什么（智能体、技能、工具、兼容的应用）、在哪儿（设备）、长成什么样（用量、连续天数、记忆）。会话是跟它说话，任务是它在做事，这页是它自己。

家当 / 装备

用户给 Agent 配的全部资源。好懂、偏工具感；「装备」带一点游戏味，和吉祥物的养成气质搭，但弱化了助理有记忆、有关系这层。

我的

移动端惯例，零学习成本。但「我的」通常装账号、设置、订单，容易又把配置招回来，正好违背这次清理的方向。

工作台

强调「在这里办事」。和会话、任务的职责重叠，不推荐。

4 · 生成式 UI 落在哪

如果定义成「它的本体」，生成式就有一个自然的解释：这一页由它来介绍自己，而不是一张固定仪表盘。

层固定生成
骨架形象 + 几块资源卡（智能体 / 助理 / 技能 / 工具 / 兼容 / 设备 / 用量）卡片顺序按最近用到的排，没用过的收起
卡片内容数量、列表、开关一句它自己的话：「这周你让我跑了 12 次性能分析，要不要把它存成技能？」
临时卡—发现新的兼容应用、某个 MCP 断了、技能 30 天没用——出现一张，处理完消失

边界：生成的只是排序、摘要和临时卡；资源本身的增删改走确定的控件，不让模型生成按钮。

5 · 还没定的

智能助理放哪：它是「资源」（一张卡）还是「会话对象」（侧栏里一行）？截图里助理同时出现在侧栏和首页。按本体页的定义，助理是它的分身，更像这页的一部分；但日常跟助理说话又是会话。
小应用的启动方式：移出一层之后，从哪进？会话里由它拉起、⌘K、还是你说的那个「比较疯的想法」。
这一页在侧栏的位置：做成一层导航项，还是挂在左下角身份栏（现在是设备名 + 设置齿轮）——点头像 / 吉祥物进入本体页，和「它」的定义最一致。
