# 分析提纲 · 已确认并据此展开完整报告

日期：2026-11-03。UX 视角。所有判断为公开资料推导，未进行触屏实机测试。

## 1. 空间指向可以成为 Agent 的上下文入口

- 证据：Cursor 当前 Design Mode 支持元素/区域/文字批注、圈画、语音说明，并带元素信息与截图（S10）；Claude Code 桌面端提供浏览器选元素入口（S08）；Android Studio 支持图片输入（S14）；Xcode 支持选择预览控件定位源码（S17）。
- 分析：这几种入口的上下文粒度不同。截图保留外观，元素选择保留结构，源码选择保留实现位置；在触屏上表达“这里”需要把这些信息绑定到同一任务。触屏的价值是否成立，要看目标选取和澄清成本，而不只是输入字符数。
- 建议：DevEco 预览增加明确的选择模式，选中组件后显示组件名/文件/设备，再允许文字或语音表达修改；不要把每次运行态点按都转成给 Agent 的指令。
- 验证：相同 UI 修改任务下，比较键鼠描述、截图附加、点选组件三条路径；记录错选率、澄清次数、完成时间。

## 2. 审阅反馈要能在没有 hover 和修饰键时完成

- 证据：Codex 文档的行评论流程包含 hover 后出现加号（S06）；Cursor 多选和父子层级选择含 Shift 与方向键（S10）；Android Studio 审阅图把 diff、接受/拒绝/自动批准及 Stop 组织在同一纵向流（S13、已存图）。
- 分析：桌面能力齐全不等于无键盘时能顺利操作。需要单独检查发现入口、命中目标、调整选区、批注、确认与回退，而不是按产品名称做简单支持/不支持判断。
- 建议：DevEco 先做持续可见的“批注/接手/暂停”，提供触控多选入口与选区调节；审阅按改动意图组织，保留展开代码与单项回退。
- 验证：断开物理键盘完成行级反馈、多选、拒绝一个改动与回退；记录误触、入口发现、恢复成功率；尺寸以实际逻辑坐标与设备规范测量。

## 3. 模拟器与折叠形态把问题带到输入路由和操作归属

- 证据：Android Emulator 官方列出嵌入工具窗口的多指限制（S16）；华为文档区分展开态小键盘与折叠态虚拟键盘（S03/S04）；Xcode Device Hub 组织设备与画面（S17）；Android Studio Agent 可以部署、截图与通过 adb 输入（S13）。
- 分析：手指在被测应用上的操作、IDE 选择组件的操作和 Agent 自动操作可能作用于同一画面。折叠、缩放、软键盘又会改变可见区与坐标。应把手势实际到达哪一层和当前谁在操作纳入设计。
- 建议：DevEco 运行预览与圈选模式显式区分；显示设备占用，人工接管后暂停该设备的 Agent 输入；姿态变更后保留任务与选中对象，重新确认截图坐标。
- 验证：覆盖嵌入/独立模拟器、多指输入、执行中接管、软键盘弹出和折叠切换；检查丢触点、误派任务、错误坐标和设备操作冲突。
