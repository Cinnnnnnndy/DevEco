# 22 冷启动分析报告 · 消融记录（终轮）

- **没有 Agent**：自己跑冷启动 trace，打开报告，从总览里找最差的一条，下钻看瀑布、对根因，点定位跳到代码自己改，改完再手动冷启动几次取平均、重扫一遍看分数。
- **有 Agent**：报告本身由 Agent·冷启动 生成，结论先行，每条根因标「证据」（trace 实测）或「推断」（按时间重叠）；点「让 Agent 修这 3 处」→ 它读 trace、写补丁（AI 行带来源竖条）→ 停下等你拍板装机（琥珀：会清掉设备上的应用数据、③ 是推断）→ 在 Mate 70 Pro 上冷启动 5 次取中位数 → 分数与瀑布回填，你接受 / 接手 / 退回。原来的总览 → 下钻 → 定位代码退为「自己看根因」次路径。
- **多 Agent**：同一份总览里 ListPage 白块是 Agent·列表 的任务在采、在修：那一行标「Agent·列表 在修」，证据归它的任务，本任务只读不重复修；复测要独占真机，第一步是等 Agent·列表 让出 Mate 70 Pro。复测证据归档到任务「冷启动修复」。

| 元素 | 结果 | 依据 |
|---|---|---|
