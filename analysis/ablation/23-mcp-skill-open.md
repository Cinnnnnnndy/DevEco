# 23 开放 MCP 与 Skill · 消融记录（终轮）

- **没有 Agent**：外部 Agent 碰不到真机，开发者在 IDE 里自己点构建、签名、装机、截图、翻 HiLog，再把截图和日志贴回给它。
- **有 Agent**：Claude Code 按任务自己调 `deveco.*` 工具，一行一个工具收在「外部调用」里；到签名这种敏感步骤停下，琥珀审批卡就地出现在调用流里（不再弹模态），顶栏胶囊写「在等你 · Claude Code 想用调试证书给 entry 签名」，点它跳过去；你选仅这一次 / 本会话 / 始终允许 / 拒绝，它接着装机、截图、抓日志。小艺从手机发来的系统意图走同一个审批队列。
- **多 Agent**：同一时刻 Cursor 在跑上架自检：它的签名按 Cursor 自己的授权放行（Claude Code 的授权另算），要装 release 包到同一台 Mate 70 Pro 时排队，写明「由 Claude Code 在用，用完自动接上，不打断它」；授权记录按 Agent 分开，可只撤其中一个。

| 元素 | 结果 | 依据 |
|---|---|---|
| 顶栏 Agent 胶囊（DemoFrame.agent：待命 / 在调 xx / 在等你 / 完成） | 新增 | 在等你只推最挡路的一件，点它跳到审批卡 |
| 授权模态弹窗（遮罩 + 对话框） | 合并成调用流 / 意图记录里的 `.ai-approve` 琥珀卡 | 模态会挡住整个 IDE，也挡住别的 Agent 的进度；审批就地出现、进同一个队列 |
| Cursor 的并发调用（签名按它自己的授权、装机排队） | 新增 | 多 Agent 的真实问题：两家抢同一台真机；授权按 Agent 分开 |
| 调用行里的参数行（`args` 等宽一行） | 删除，只在审批卡的命令块里出现 | 放行的调用不需要人读参数；要你拍板时才需要看 |
| 调用行里的客户端灰胶囊 | 改为正文里一行浅色字 | 去掉装饰胶囊，信息不变 |
| 「授权时的四个选项」说明块 | 删除 | 解释界面本身：四个按钮就在审批卡上，卡底一句说明「只对这个 Agent 生效」 |
| MCP 能力页底部「项目 / 设备 / 调用记录」三行 | 删除 | 项目、设备在顶栏已有；调用记录路径写进完成那一句 |
