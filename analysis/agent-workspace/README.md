# Agent 工作台：AI Coding 下的默认视图

原型：[`demos/31-agent-workspace/index.html`](../../demos/31-agent-workspace/index.html)（外壳 `demos/_shared/workspace.js / workspace.css`，结果区用 `demos/_shared/stage.js`）

## 1. 为什么默认视图不再是「文件树 + 编辑器」

用了 AI Coding 之后，开发者大部分时间不打开文件树，也不逐行读代码。他的注意力按下面六步走：

| 他在做 | 他要看的 | 现在的 IDE 给他的 | 原型里补上的判断 |
|---|---|---|---|
| 1 说清要什么 | 输入框，加上它理解成了什么（意图 / 计划） | 挤在右边的聊天侧栏 | 计划要**能改**（改一步、删一步、加一步），「开始」才是主按钮；计划里要写清会碰到哪个 Agent 的地盘 |
| 2 拍板 | **在等我的决定** | 淹没在长回答里 | 多 Agent 时决定会同时冒出好几个，所以要一个**统一队列**、按阻塞排序；胶囊只推最挡路的那一件，不挡路的不抢 |
| 3 看结果 | **跑起来的应用**，sm / md / lg 多形态 | 另开模拟器，自己切 | 在鸿蒙电脑上应用原生运行，每个 Agent 可以各开一套窗口并行验；真机只有一台，要有**租约和排队** |
| 4 审改动 | 按风险排好、只看需要人看的几处 | 文件树 + 编辑器挨个点开 | 真正需要人判断的是「删了有意义的东西」「产品取舍」「两个 Agent 撞了」；机械改动折起来；每一处都标是谁写的 |
| 5 信不信 | **证据**：构建、检查、多设备、性能改前改后 | 散在 Build / Run / Profiler | 证据要**归档到任务**、写明哪个 Agent 在哪台上跑的；性能证据会反过来推翻一个决定（GridRow 掉帧 → 改用 lanes 重做） |
| 6 接手细节 | 编辑器、可视化修改 | 编辑器——现在的 IDE 唯一优化过的一步 | 编辑器从改动行或结果上的元素就地打开；你手改一个值，Agent 读到并接着做完（跟着调预取行数、重验那一台） |

文件树 + 编辑器只服务第 4、6 步的一部分，所以它们退到「文件」次级页签和按需分栏里。

## 2. 布局：每一区回答哪一步

| 区域 | 回答哪一步 | 原型里是什么 |
|---|---|---|
| 顶栏中间的 Agent 胶囊 | 2 | 只显示最需要你的那一件（或当前任务在做什么 + 用时），点它跳过去 |
| 左 · 在等你队列 | 2 | 所有 Agent 的待决放一处：挡住它 > 挡住合并 > 不挡路 |
| 左 · 任务列表（主导航） | 1、2 | 每行一句目标 + 哪个 Agent + 状态（ai.css 状态机）；「文件」是次级页签，只列本次改动和它读过的，完整树按需展开 |
| 中 · 当前任务 | 1、2 | 你的话 → 它理解成 · 计划（可改）→ 轨迹（工具调用收成一行）→ 结论先行的回答卡；在等你的决定置顶 |
| 右上 · 结果（最大） | 3 | MallApp 在本机原生运行的 3 个窗口 + 1 台真机；它验哪台、你光标在哪个断点，哪台就上台（台前调度），侧边写着每台归谁用 |
| 右下 · 改动 | 4 | 按意图分组、按风险排序，「只看需要你看的」；冲突处两边的写法并排，一键定 |
| 右下 · 证据 | 5 | 构建 / ArkTS 检查 / 多设备（含真机租约）/ 滑动帧率改前改后，一排结论胶囊，点开看详情 |
| 状态栏 | 2、3 | 几个 Agent 在跑、在等你几件、本机窗口与真机数 |

## 3. 编辑器什么时候出现

只在「接手」时出现，以分栏就地打开并定位到行，关掉回到工作台：

- 从改动行点「接手」；
- 从结果上点某个元素（ProductCard）→「接手改代码」；
- 从「文件」页签点一个文件。

光标落在只影响某个断点的代码（`lg: 3`）上，对应设备自动上台；你改完值，那一台热重载，Agent 把你的手改当成新的前提继续（原型里：`lg 3 → 4` 后它把 `cachedCount` 改成 8，并只重验平板）。你改的行不打 AI 标记——人是默认作者。

## 4. 和经典视图怎么切

顶栏「工作台 / 编辑视图」一键切。编辑视图是经典 IDE 布局（项目树 + 编辑器 + 右侧 DevEco Code + 底部 Run），**读写同一份任务状态**：同一个在等你队列、同一段计划与轨迹、编辑器里是同样带来源标记的行、同样可编辑的 `lg` 值、同样的证据胶囊。在任一处拍板或手改，另一处立刻一致。适合一口气深写代码的时候。

## 5. Agent 在其他 30 个 demo 里的角色

原则：Agent 做累活，你做判断；每页都要答得出「它在做什么 / 你做什么 / 它在哪儿等你」，以及**多个 Agent 同时在跑时怎么办**。

| demo | Agent 做 | 你做 | 多 Agent 时 |
|---|---|---|---|
| 01 布局预设 | 开始干活 / 在等你 / 验证时自动切对应布局 | 定布局偏好 | 布局跟着「最需要你的那个 Agent」切，不跟着每个 Agent 抖 |
| 02 场景化体检 | 按上架规则扫全工程，每条出补丁，批量修完回归 | 挑哪些接受 | 体检补丁和别的 Agent 改到同一文件时先 rebase 再问；回归占设备要排队 |
| 03 症状调优 | 读 trace 定位、出补丁、同手势复测、判显著性 | 说哪里卡、接受补丁 | 复测需要独占设备（其他 Agent 的负载会污染帧率），设备上写「调优在复测，勿动」 |
| 04 安卓转化 | 对照两版找差异、按原版改、跟进安卓新提交 | 判需人工的项 | 转化 Agent 与功能 Agent 改同一页面时按意图分组，冲突进在等你队列 |
| 05 三处就地对话 | 就地回答、改码 | 问、接受 | 就地问的是后台哪个 Agent 的产出，回答里标出来 |
| 06 语音开发 | 听写意图、执行 | 说 | 一句话可以派给不同 Agent，派之前复述「交给 Agent·多语言」 |
| 07 Agent Team | 分工、交接、冲突处理 | 编排、裁决 | 本身就是多 Agent：统一在等你队列与本页一致 |
| 08 结论先行 | 长任务结论推到实况窗 / 手机 | 读结论、拍板 | 实况窗只推最需要你的那一个 Agent，其余排在队列里 |
| 09 可视化编程 | 连线后补 handler 与异常分支，画布上标出它补的 | 画流程、连线 | 画布节点标归属；两个 Agent 补同一个 handler 时并排给两版 |
| 10 可视化调优 | 读火焰图 / 内存 / 并发泳道，解释异常并给补丁 | 点异常处 | 泳道里标出是哪个 Agent 的 TaskPool 任务在抢主线程 |
| 11 意图确认 | 出可改的计划、按计划执行、标偏离 | 改计划、放行 | 计划里写明会碰哪些别的 Agent 正在改的文件 |
| 12 自动化 Workflow | 按存下的流程跑（打包、发测试） | 触发、发前确认 | 流程之间争设备 / 签名时排队，发前确认进统一队列 |
| 13 D2C 与可视化修改 | 设计稿生成代码；你在画面上改的合进源码并处理冲突、保留来源 | 圈 / 拖 / 说 | 人优先：你一动它暂停；两个 Agent 改同一组件按本页的冲突卡处理 |
| 14 AI 协作时间轴 | 每条改动记来源、可挑着退 | 挑着退 | 时间轴按 Agent 分泳道，退一条只退那个 Agent 的 |
| 15 跨端接续 | 离开工位把任务变实况窗，回来原位接上 | 碰一碰接续 | 接续的是整个在等你队列，不是单个对话 |
| 16 多设备验证 | 并行跑、逐处预判「适配 or 缺陷」并给修复 | 确认判定 | 每个 Agent 各占一套设备并行（本机窗口 + 云端多开）；真机租约可见 |
| 17 模拟器多端 | 一多检查：逐形态截图比对，它检查哪台哪台上台，出修复 | 接受修复 | 台前调度侧边写每台归谁；被别的 Agent 带坏的亮红点并写是谁 |
| 18 分布式调试 | 对齐两端日志、判断断在交接第几步、给根因和补丁 | 定断点、看结论 | 调试会话独占：别的 Agent 要装包到这两台时先问 |
| 19 远端调试 | 借机（排队、选机位）、在远端设备上跑复现脚本 | 看结果 | 远端机位按 Agent 排队，占用时长与释放时间写在设备卡上 |
| 20 连接状态 | 诊断卡在第几步并自动修，危险步骤才问你 | 确认 | 重启 hdc 会打断所有 Agent 的会话：先列出受影响的 Agent 再问 |
| 21 智慧胶囊 | 状态常驻，一键升到实况窗 | 瞥一眼、点进去 | 胶囊只推最挡路的一件，显示「还有 N 件」 |
| 22 / 28 分析报告 | 生成报告，每条结论标「证据 / 推断」，「让 Agent 修」出补丁 | 读结论、拍板 | 报告的证据按任务 / Agent 归档，不混 |
| 23 MCP 与 Skill 开放 | 按任务调入技能与工具，调用可见 | 授权 | 授权按 Agent 分开，可只撤某一个的 |
| 24 插件开放 | 把模拟器 / Profiler / 三方插件当工具调用 | 授权 | 同一插件实例被两个 Agent 调用时排队并标来源 |
| 25 手机客户端 | 对话里直接真机调试 | 在手机上看、批准 | 手机上看到的是统一队列的第一件 |
| 26 IDE Web / Lite | 轻量环境里跑同一个任务 | 快速验证 | 网页端能看到桌面端其他 Agent 的状态与队列 |
| 27 云端模拟器 | 跑旅程、修失败格、只重跑那台 | 看矩阵 | 云端多开 = 每个 Agent 各一套，互不抢；矩阵格标是哪个 Agent 跑的 |
| 29 多语言 | 加语言、翻译、复数、RTL 预览与修复 | 审阅 | 本页的 Agent·多语言：和列表 Agent 撞在 ProductCard 时进统一队列 |
| 30 折叠屏开发 | 圈选→改，下屏显示它干活的进度 | 圈、看 | 下屏只显示和上屏当前文件相关的 Agent，其余收成一行 |

## 6. 待验证的假设

1. **开发者愿意把「结果」而不是「代码」当主视图**：需要看真实用户在 AI 任务里切到编辑器的频率与时长；若大多数任务仍要读完整 diff，编辑视图应更靠前。
2. **按风险排序能把审阅压到 2–3 处**：风险判断（删了带注释的代码、产品取舍、跨 Agent 冲突）需要在真实工程里标定误报 / 漏报。
3. **统一在等你队列比各面板各弹更少打断**：同时 3 个以上 Agent 时，按阻塞排序是否足够，还是要加「我现在只看这一个任务」的专注模式。
4. **本机原生运行能替代大部分模拟器验证**：窗口按设备逻辑尺寸跑与真机的差异（刷新率、系统栏、折痕、传感器）有多大，哪些证据必须真机复核。
5. **真机租约可被接受**：Agent 占用真机时，开发者能否接受「排队 / 让路」而不是直接抢；「你拿起设备 Agent 自动暂停」的判定是否可靠。
6. **手改后 Agent 接着做不会越权**：它读到手改后顺手改相邻代码（cachedCount）是帮忙还是越界，需要一个「只验证、不再改」的开关。
7. **两种视图共享状态足以支撑深度写码**：长时间写代码时，工作台的结果区是否仍有价值，还是经典视图应默认带一个小结果窗。
