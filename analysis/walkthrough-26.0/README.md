# DevEco Code 26.0 融合版本 · 上线走查

主线：从安装到使用。报告：[`REPORT-走查报告.html`](REPORT-走查报告.html)，启动页「版本走查」分类下的卡片直达。

## 目录

| 路径 | 放什么 |
|---|---|
| `images/` | 走查截图，按收到顺序编号 `01.webp`、`02.webp`…（.png / .jpg 也认）。报告按编号自动取图，缺图时显示占位，标注照常对齐 |
| `flows.md` | 按任务流梳理出来的流程清单（第 1 步产出） |
| `REPORT-走查报告.html` | 最终报告：HTML 单文件、CSS/JS 内联、零外链，双击即开；截图以相对路径引用 `images/` |

## 流程

1. **收素材**：截图放进 `images/`，每张注明所属版本界面（DevEco Studio / Code / CLI）与入口位置。
2. **按任务流梳理**：把页面串成用户任务流——每条流写清「谁、在什么场景、要完成什么」，列出起点 → 各步骤 → 终点，每步对应一张或几张页面。缺页、断点、无法串起来的页面单独列出。产出 `flows.md`，先确认再往下走。
3. **逐步走查**：沿每条流一步一步过，用设计检查 skill 对照规范逐页检查（IDE 页面对照 `deveco-intui-kit` 的 token 与组件规范、`deveco-windows-ui` skill 的 Int UI 组件约定）。每个问题记一条：流程 / 步骤、页面位置（截图框选）、现象、违反的规范条目、严重度、改法建议。
4. **汇总出 HTML 报告**：总览（流程数 / 页面数 / 问题数按严重度）→ 按流程逐步展开问题（版式见下）→ 问题清单总表；登记到 `site/catalog.js`（`view` 改 `'doc'`、补 `href`）并出缩略图。

## 报告版式

- **左图右文**：每一步一行，左边是页面截图，右边是这一页的问题列表。
- **问题直接标在图上**：在截图上框出问题区域，框角放编号圆标（①②③…，颜色按严重度）；右侧列表同编号一一对应，每条写现象、违反的规范、严重度、改法。
- 图与文联动：悬停右侧某条，图上对应框高亮；点图上的框，右侧滚到那一条。
- 标注坐标按截图原始像素（2000 × 1125）记 `[x, y, w, h]`，渲染时换算成百分比，缩放不偏。问题数据都在报告底部 `STEPS` 里，新增截图或问题只改那一段。

走查规范（问题分类与严重度口径）以提供的规范为准，拿到后补到这里。
