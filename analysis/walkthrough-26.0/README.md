# 26.0 版本走查报告

启动页「版本走查」分类下的卡片，目前是占位（`view:'sketch'`），报告出来后改成 `doc` 并补 `href`。

## 目录

| 路径 | 放什么 |
|---|---|
| `input/` | 走查页面原件：截图 / HTML / 录屏，文件名带「流程编号-步骤编号-页面名」，如 `F1-03-工程创建向导.png` |
| `flows.md` | 按任务流梳理出来的流程清单（第 1 步产出） |
| `REPORT-走查报告.html` | 最终报告：HTML 单文件、CSS/JS 内联、零外链，双击即开；截图以相对路径引用 `input/` |

## 流程

1. **收素材**：走查页面放进 `input/`，每张注明所属版本界面（DevEco Studio / Code / CLI）与入口位置。
2. **按任务流梳理**：把页面串成用户任务流——每条流写清「谁、在什么场景、要完成什么」，列出起点 → 各步骤 → 终点，每步对应一张或几张页面。缺页、断点、无法串起来的页面单独列出。产出 `flows.md`，先确认再往下走。
3. **逐步走查**：沿每条流一步一步过，用设计检查 skill 对照规范逐页检查（IDE 页面对照 `deveco-intui-kit` 的 token 与组件规范、`deveco-windows-ui` skill 的 Int UI 组件约定）。每个问题记一条：流程 / 步骤、页面位置（截图框选）、现象、违反的规范条目、严重度、改法建议。
4. **汇总出 HTML 报告**：总览（流程数 / 页面数 / 问题数按严重度）→ 按流程逐步展开问题（截图 + 标注 + 改法）→ 问题清单总表；登记到 `site/catalog.js`（`view` 改 `'doc'`、补 `href`）并出缩略图。

走查规范（问题分类与严重度口径）以提供的规范为准，拿到后补到这里。
