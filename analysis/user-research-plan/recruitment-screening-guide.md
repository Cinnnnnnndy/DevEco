# 外部用户招募筛选与预约说明

版本：2026-11-06 · 配套15题精简问卷

问卷只做初筛，预计4–6分钟。分组和研究邀请由预约核验确认，问卷页面为审阅稿，不收集答案。深入需求、任务回溯和满意度保留在正式访谈。

## 一、招募范围与主配额

外部近6个月有本人鸿蒙任务者为常规对象；更早经历作为历史 / 停用专题核验。内部用户由业务团队定向邀请，不填外部问卷，近3个月实际使用DevEco，来源单独记录。

| 画像主类 | 累计建议区间 | 核验依据 |
|---|---|---|
| P1 头部互联网及同类大型研发团队 | 12–16人 | 多团队协作、组织级工程平台或专门工具链支持 |
| P2 中厂 | 8–10人 | 稳定分工，工程支持主要围绕业务项目 |
| P3 小团队与个人开发者 | 10–14人 | 少量成员或个人承担多环节、自行组合工具 |
| 合计 | 30–40人 | 多轮累计独立人数，复访只增加人次 |

目标比例约40%、25%、35%，是研究覆盖参考。内部6–10人包含在总数内，按工程体系归组；生态伙伴记业务标签。Q01–Q04给出行业、岗位、组织研发人数和项目人数，预约时核实协作与组织背景，不能只看人数或公司名分类。

同一外部企业原则上≤2人，头部配对访谈≤3人，争取3–4家外部重点企业；内部≥3个业务团队，开发≥4人、测试 / 发布≥1人。P3中小团队和独立开发 / 学习者分别争取≥4人。

## 二、题目、跳题与用途

| 题号 | 用途 | 配置 |
|---|---|---|
| Q01–Q04 | 行业、岗位、组织与项目人数 | 允许未知或无所属组织；先记录事实，后判画像 |
| Q05 | 项目数量 | 0个结束；记不清继续核验，不因项目少排除 |
| Q06 | 最近本人任务时间 | 近6个月常规；更早或未知进入核验 |
| Q07 | 高频任务及流程覆盖 | 多选最多3项；未选不代表没做过 |
| Q08 | Studio近4周频率 | 区分近期、历史、从未与未知 |
| Q09 | Studio高频模块 | Q08从未使用时跳过；最多3项，不确定名称互斥 |
| Q10 | Code使用阶段 | 所有人回答；未用不影响资格，频率和细节预约补问 |
| Q11 | AI近4周频率 | 高频≥3天 / 周，低频少于3天；未用保留停用 / 从未标签 |
| Q12 | 最常用AI工具 | 仅近期使用者回答；跳题记未展示 |
| Q13 | 探索行为 | 数量两项互斥，没有尝试及记不清分别互斥；用于先锋候选 |
| Q14 | 本次意愿 | 暂不参加结束；先了解不等于已确认 |
| Q15 | 自愿联系 | 愿意 / 先了解者展示，选填；未留不进入预约，不另加同意题 |

问卷共15道编号题，包含意愿和联系方式，没有隐藏的必答子题。其他项补充均选填。正式平台需验证隐藏必填、互斥、最多选项及退出路径；试填3–5人覆盖三类画像、AI未用者和Code仅试用者，以实际时间校准4–6分钟估计。

## 三、筛选顺序与状态

先确认本人经历与时间，再核验画像、岗位和产品使用，最后按缺口安排。未用AI、未上架或拒绝录制不影响资格；专家意见和团队转述不替代本人任务。

| 状态 | 判断与处理 |
|---|---|
| 待核验 | 经历、分组或意愿不清楚，先联系核实 |
| 本批入选 | 基本条件确认，符合本批人群或场景缺口 |
| 配额候补 | 条件符合但满额、组织集中或时间不合适 |
| 专题补充 | 历史 / 停用经历或其他协作角色，由负责人记录纳入理由 |
| 本轮不纳入 | 核实无本人经历，或不愿参与 / 未授权联系 |
| 已撤回 | 停止联系，按已告知约定处理资料 |

筛选状态、场次预约和完成状态分别记录。只有完成正式访谈、观察或任务测试才计为独立参与者；问卷、预测试或预约不计入。每人统一编号，复访不重复占新增名额。

## 四、预约时只补本轮需要的信息

一次约5–10分钟，按用户角色选问；其他信息在正式访谈确认，不将旧长问卷整套口头重问。

| 必要信息 | 简短核验 |
|---|---|
| 真实鸿蒙任务 | 最近一次何时、做了什么、本人操作和结果如何？允许练习、暂停及失败案例 |
| 画像与协作 | 组织有哪些工程平台和支持？本人项目怎样分工、工具由谁选？ |
| 项目与版本 | 原生ArkTS / ArkUI、迁移、跨平台还是框架工具交付？设备、SDK / API、Studio / Code版本按本轮需要核实 |
| 使用与熟练度 | 选本轮目标产品，近4周大致频率？可独立完成哪两类岗位任务？用一例核验 |
| 先锋候选 | 对照Q13确认近3个月≥2个新工具 / 主要新功能、实际项目和流程调整；补一例限制与应对 |
| 意见影响力 | 仅相关专题补问近6个月分享、指导或选型及≥2次实际使用 / 协作反馈，核验一例影响 |
| 专题条件 | 按任务补问其他平台经验、工程接入、开发准备或项目阶段；不要求所有人具备这些经历 |
| 参与安排 | 确认具体形式、时间、资料展示方式及录音 / 录屏；复访单独确认 |

先锋、熟练、意见影响力是可重叠标签，不是淘汰门槛。先锋争取6–8人；熟练争取10–14人（近4周每周≥1天，独立完成≥2类相关任务）；意见影响力争取3–5人。上述为本期操作定义，核验后确认；未问到记未评估，不能记不满足。Code、Studio与其他AI工具的熟练度分别记录。

## 五、覆盖、排期与资料

岗位约开发55%、测试 / 质量 / 发布17%、工具链 / 平台17%、技术负责人11%；AI高频、低频、近月未用各约三分之一。鸿蒙年限≤3个月、超过3至12个月、超过12个月约28%、33%、39%，年限预约按需补记，不等同于能力。流程、平台、设备缺口结合本轮任务定向补招，不要求所有交叉格都填满。

本期准备、编码、验证、签名发布各争取≥6人；暂停项目3–4人；Android经验≥8、iOS≥6、非手机终端≥6，允许重叠。以上是覆盖参考，不从目的性样本推算生态分布。

两位交互各30%，合计约3人日 / 周，先安排5–8人，执行周约2场。后续形成性测试每轮5–8人，综合评估暂估10–12人，按证据与可用版本推进。每轮统计人次，本期累计去重人数；已完成首次研究者复访不扣新增名额。

公开页面只保留设计稿、规则和空白台账。真实答案、联系方式、录音和礼品登记存放在团队受控位置；正式发放前展示联系渠道、信息用途、访问范围、保留期限和撤回方式。联系方式与答案分开保存，按编号关联；停止联系已撤回者。

调整题号或标签时，同步更新研究计划、问卷、筛选规则、访谈提纲与台账。
