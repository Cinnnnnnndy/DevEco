# 招募筛选与配额执行说明

版本：2026-11-05。仅供研究与招募团队使用，不作为受访者问卷正文。配套文件：`recruitment-questionnaire.md` / `.html`。

## 样本配额

以 36 位独立受访者作为排期基准，允许结合场景覆盖在 30–40 人内调整；不是概率抽样，不据此推算生态人群占比。复访不重复计人数。

| 主分组 | 人数 | 占总样本 | 核验要点 |
|---|---:|---:|---|
| 外部互联网头部厂商 | 8 | 22.2% | 客户团队提前确认名单；覆盖 3–4 家，一线与平台角色配对 |
| 外部其他中大型企业 | 7 | 19.4% | 非头部互联网与非互联网行业，记录工程方式 |
| 外部初创 / 小团队 | 5 | 13.9% | 2–10 人项目团队仅为参考，需核实组织背景 |
| 外部个人 / 学习者 | 6 | 16.7% | 有实际项目或练习工程，不以是否商业化筛选 |
| 外部生态伙伴 | 2 | 5.6% | 亲自参与框架、三方库或开发服务交付 |
| 华为内部 DevEco 开发者 | 8 | 22.2% | 近 3 个月实际使用，至少 3 个业务团队 |
| 合计 | 36 | 100% | 外部 28 人、内部 8 人 |

每人只占一个主分组。先内部 / 外部分流，再按本次分享的项目身份划分伙伴、个人或企业；企业按预先确认的名单及组织背景分组。Q3 未提供组织名称者可先用代称，在预约中自愿核验；不能确认头部身份时不强行归类，也不向其索要保密资料。中大型企业中的小项目组不自动归为初创。

角色交叉配额：一线开发 20、测试 / 质量 / 发布 6、工具链 / AI 平台 / 效能工程 6、技术负责人 4。按主要职责计数，兼任留作副标签。设计 / 产品等其他角色可作为专题补充，若计入主样本须明确调整角色配额并记录。

AI 频率交叉配额：高频、低频、近月未用各 12 人。高频为近 4 周平均每周 ≥3 天；低频为用过但平均每周 <3 天；近月未用再分从未使用和曾用后停用，两类均争取覆盖。鸿蒙经验交叉配额：≤3 个月 10 人、>3–12 个月 12 人、>12 个月 14 人。

具体流程、设备、平台为多选标签：准备、编码、验证、签名 / 发布各争取 ≥6 人；暂停 / 放弃项目 3–4 人；Android ≥8 人，iOS ≥6 人，非手机终端 ≥6 人，可重叠。不要为了填满所有交叉格子扩大样本。

## 问卷设计取舍

参考其他项目“用户是谁 → 实际怎么用 → 能否参与”的筛选思路与自然直接的措辞，围绕鸿蒙项目重写为 12 道核心题，另设 S0 知情同意及 C1 联系授权。预计 5–8 分钟，需经试填校准。没有沿用云服务器资源数量、控制台形态、活动日期、奖项或评审机制。

报名阶段识别人群和经历，预约阶段核实配额标签，正式访谈追问需求与原因。问卷不替代深访，也不直接产出需求排名或满意度结论；不把参与奖励设计成对观点质量的评奖。奖励、时间及渠道确认后另行说明。

## 入选与补充规则

- 主样本须同意筛选、有可核实的本人任务经历，并愿意接受访谈安排。外部优先近 6 个月参与者；内部需近 3 个月实际使用 DevEco。题目间不一致时先澄清，不直接认定无效。
- Q04 尚未亲自参与：结束本轮开发者招募，不展示其余题目及联系方式。Q06 近 3 个月无任务：继续填写，预约时确认最后实践时间；3–6 个月者仍可纳入外部主样本，超过 6 个月者进入历史 / 停用经历补充池，必要时纳入并记录理由。
- Q05 外部未用 DevEco，但通过其他工具参与鸿蒙工程或平台接入：可纳入对应专题；内部不满足近期使用条件者进入补充池。
- Q06 一句话只有概括态度而无任务信息：预约前简短核实，不要求截图、代码或保密证明。仍无本人经历者不进入主样本。
- AI 未用、无负面反馈、未上架、拒绝录音录屏均不构成排除理由。不能以痛点多少或熟悉 Spec / MCP 等术语筛人。
- Q12 先了解安排者：仅进入沟通池；确认愿意后预约。暂不参与者结束，不展示联系信息题。
- C1 不同意留下联系方式：结束报名，不进入预约名单，不从其他渠道补抓个人信息。
- 纯专家意见另记，不充当实际用户证据。内部与外部分别分析，并标注内部支持条件。

## 跳题与问卷平台配置

| 条件 | 后续路径 |
|---|---|
| S0 不同意 | 结束，不保存未同意答卷 |
| Q04 尚未参与 | 隐藏项目状态，结束，不展示联系题 |
| Q05 从未使用 | 隐藏产品子题，继续 Q06 |
| Q06 近 3 个月无任务 | 继续，真实任务填更早经历，标记预约补充核验 |
| Q08 高频 / 低频 / 曾用后停用 | Q09 → Q10 |
| Q08 从未使用 | 跳过 Q09，隐藏 Q10 的 AI 材料补充题 |
| Q11 亲自接入或试接 | 展示选填的一例；其他选择不展示 |
| Q12 暂不参与 | 结束，不收集联系信息 |
| Q12 愿意 / 先了解 | 展示 C1 |
| C1 同意 | 展示称呼、一种联系渠道及选填时段；不同意则结束 |

组合题拆成独立子题，如 Q04a 实践年限、Q04b 项目状态；Q05a 最近使用、Q05b 产品；Q06a 高频任务、Q06b 一句话经历。条件隐藏题不能设为全局必填。“没有 / 不清楚 / 记不清”等按题意配置互斥；Q06 和 Q09 最多选 3 项，其余多选不限项。“其他”可补充说明。

问卷页面的“配置说明”、配额及筛选规则仅供搭建使用，正式发放时不向受访者展示；不显示“符合 / 不符合预期答案”等文案。若试填超时，可将 Q10 AI 材料选答及 Q11 接入例子移到预约阶段。

## 预约时补充核验（按人群选问，不要求每人全答）

| 核验主题 | 简短提问 | 用途 |
|---|---|---|
| 企业主分组 | 业务领域是什么？可否提供组织代称或由客户接口人确认类别？目前是自研、外包还是生态服务项目？ | 区分头部、其他中大型、初创；不只看项目人数 |
| 实际参与与频率 | 最近一次任务何时发生？近 3 个月大致每周做几天？DevEco 用什么版本？ | 核验近期参与；与 AI 使用频率分别记录 |
| 技术与终端 | 原生 ArkTS、跨平台还是迁移项目？涉及哪些设备？ | 补齐开发方式及非手机终端标签 |
| 角色与流程 | 除主要职责，是否直接负责测试发布或工具链？实际做过哪一步？ | 副角色与全流程覆盖，不只依据高频前三项 |
| 内部支持 | 平时主要通过公开文档、同事还是产品技术团队获得支持？ | 标注内部 / 外部支持差异，不要求联系人 |
| AI 未用 / 停用 | 是近期没任务、已有方式足够、受条件限制，还是其他原因？ | 保留不同原因，不将未用视为能力不足 |
| 参与安排 | 哪些时段方便？是否只口述，或愿意展示脱敏材料？录音 / 录屏是否可另行确认？ | 拒绝展示或录制不影响入选 |
| 后续邀请 | 是否愿意在本次结束后另行接收复访或原型体验邀请？ | 单独记录许可，拒绝不影响本次访谈 |

Spec 的保存与更新、AI 任务跟进与接管、代码审查和二次编辑、测试验收、能力输入输出和调用形式等保留在正式访谈，先从具体经历展开，不用术语测试筛选用户。

## 与研究目标的对应

| 研究目标 / 问题 | 筛选题目 | 后续用途 |
|---|---|---|
| 人群与项目差异，RQ1、RQ6 | Q01–Q04，预约补充行业 | 确认客户、角色、团队规模、实践经验与项目阶段 |
| 开发全流程与质量验收，RQ2、RQ4 | Q06、Q09 | 找到实际任务参与者，访谈再追问控制与验收 |
| AI 使用边界与控制，RQ3 | Q08–Q09 | 保留高低频、停用与从未使用对照 |
| 平台体验差异，RQ5 | Q07 | 邀请有实际跨平台经历者 |
| 工具链与头部能力开放，RQ6、RQ9 | Q02、Q03、Q11 | 邀请接入执行者和平台负责人，不预判所需形式 |
| AI 开发准备与生态 Spec，RQ10–RQ11 | Q10 | 记录现有材料与规则，访谈探索组织、传递与缺口 |
| 改善优先级，RQ7 | Q06 任务线索 | 正式访谈开放追问，不在筛选时要求给方案排序 |
| 后续研究条件，RQ8 | Q12、C1，预约补充 | 确认本次意愿、记录方式及后续邀请许可 |
| 竞品趋势研究 | Q05、Q07、Q09、Q11 | 识别工具使用的对照场景，工具名称不直接作为优劣证据 |

## 执行与资料管理

发放前补齐并向受访者展示研究团队、联系渠道、信息用途与访问范围、保留期限、撤回方式；不发布带空白占位的正式采集表。当前 HTML 是审阅稿，无提交接口，不存储答案。活动时间与礼品如未确认，不作具体承诺；不要求匿名观点公开共享。

仅收集一种联系渠道，联系方式与研究答案分开保存，以参与者编号关联；公开报告仅展示汇总或脱敏内容。复访仅联系单独授权者，每次参与均重新确认。不得将真实答卷或联系方式提交至公开 Git 仓库。

台账字段：参与者编号、渠道、主分组、组织代称、主 / 副角色、最近任务及 DevEco 使用、经验、AI 频率与停用标签、流程 / 平台 / 终端、支持条件、筛选 / 预约 / 完成状态、复访许可、调整理由。个人联系方式单独管理。

先安排 3–5 人试填，覆盖内部用户、外部企业和未用 AI 者。验证拒绝同意、尚未参与、停用 AI、未用 DevEco、隐藏必填、拒绝联系方式及手机展示；记录实际耗时和理解偏差后再发放。

每周核对已完成访谈的配额，预约与候补另列；先补缺失客户类型和角色，再兼顾 AI、经验及其他标签。同一外部企业原则上 ≤2 人，头部厂商配对访谈可 ≤3 人；失约不计为完成样本。

## 不同人群的填写路径检查

| 人群 | 必须能够表达的经历 | 筛选与后续处理 |
|---|---|---|
| 头部互联网厂商 / 其他中大型企业 | 企业身份、组织类型、主要角色、团队人数及工具接入经历 | 根据客户名单与组织背景区分；不要求本人自评“头部”，同企业覆盖平台与一线角色 |
| 初创 / 小团队 | 初创身份、独立或多人协作、准备与交付任务 | 组织类型与团队规模分开记录，大企业小项目组不归为初创 |
| 个人开发者 / 学生 / 学习者 | 独立项目、练习工程、迁移、未上架或暂停经历 | 不要求商业化、上架或 AI 使用经验；仍需有本人实际任务 |
| 生态伙伴 / 工具链人员 | 框架、库、测试服务或平台接入交付 | Q04 的项目阶段可填交付维护；不因未开发应用或无上架经历排除 |
| 华为内部 DevEco 用户 | 实际业务项目、开发 / 测试 / 工程职责 | 近 3 个月实际使用，跨业务团队覆盖；内部支持条件在预约时单独记录 |
| 测试 / 发布与技术负责人 | 验证、发布、技术决策与协作任务 | 不要求日常主要写代码；核验其直接参与的具体任务 |
| AI 低频 / 停用 / 从未用者 | 使用频率及非 AI 工作方式 | 从未用者跳过 Q09，继续回答通用准备材料；不因未用 AI 排除 |
| 跨平台 / 第三方工具使用者 | Android、iOS 等经验及鸿蒙任务 | 区分 AI 在鸿蒙还是其他平台使用；外部未用 DevEco 仍按真实任务判断专题适配 |

Q01 的组织类型子题仅对外部企业 / 团队展示，其他身份跳过；Q08 的 AI 使用平台补充仅向曾用者展示且为选填。试填除内部、企业与未用 AI 者外，还应检查个人初学者和生态工具链角色的路径；可在同一批 3–5 人中交叉覆盖。
