鸿蒙开发者用户旅程图（总）

一条从进入项目到交付维护的总旅程，按开发者角色分泳道。每接入一场新访谈，就往对应角色和小阶段补证据，没有的角色或步骤直接新增。版本 2026-11-27，已访 4 人（I01、I02、I03、I04），覆盖 4 个角色。

怎么读

  • 列：8 个大阶段、32 个小阶段，是所有角色共用的骨架。
  • 行：先是“所有开发者”的通用步骤，再按角色展开做法、想法、工具、原话、卡点，最后是研究判断。
  • “证据覆盖”标出每个小阶段有几个人支撑，弱的地方是下一场访谈要补问的。

哪些是事实，哪些是判断

  • 做法、工具、原话来自访谈；原话逐字核对过转写，〔 〕内为补字。
  • 想法是对受访者说法的转述。
  • 情绪、角色画像的一句话、行为倾向、异同和机会点是研究判断。
  • 灰底虚线框是低价值证据（时效或代表性弱），只作参考，不计入证据人数。
  • 样本还少，不代表所有鸿蒙开发者。

还没访到的角色

  • R5 工具链／平台人员　负责流水线、CI 或内部平台接入
  • R6 停用或未用 AI 的开发者　试用后放弃，或从未用 AI 开发
  • R7 华为内部 ArkTS 应用开发者　内部团队用 ArkTS 交付应用或框架

系统底层开发者

R1　代表受访者 I01　交付 C++ 系统组件，ArkTS 只用来写测试 demo；质量要求极高，靠人工评审把关

AI 写得快，但每一行都要有人看过。

背景

  • 做 ETS Runtime 的内存管理，交付 C++ 的 .so
  • GC 组差不多 10 人
  • 之前实习做 Java Web，没做过安卓、iOS
  • ArkTS 只用来写自测试 demo

想达成什么

  • 缩短 GC 耗时、省内存
  • 不影响其他功能，不出稳定性问题
  • 需求代码一次过 review

平时怎么做

  • 需求代码：蓝区 VS Code 远程写 C++
  • demo：黄区用 CodeAgent 写，两三轮对话
  • 看日志和 trace 判断对不对
  • 全组 review，SE 把关

常用工具

VS CodeDevEco Studio（demo、实时日志）CodeAgentOpenCodeCodex 类工具（存疑）内部 trace 工具

和 DevEco 的关系

Studio 用于写 demo 和看实时日志，没用过 Profiler。访谈里首次细看 GUI 版 Code：想放侧边栏，问“和直接开个 CLI 有什么区别”。是否用过 Code 前后说法不一，待核实。

卡在哪

  • 黄区真机、蓝区 AI 来回搬日志
  • AI 加保底、用没人用过的方案
  • SDD 交付件要一直维护
  • 崩溃的报错行不一定是根因

需要什么

  • AI 沿用已有方案和时序，改动最小
  • 说明遵守了哪些规范、跑过哪些用例
  • 对话和代码并排，改动能对应到文件和行
  • 集成进 Studio 的 AI 要和 Studio 工具打通

行为倾向研究员判断；实心是本角色，空心是其他角色

AI 托管型多端应用开发者

R2　代表受访者 I02　同一产品做三端，AI 全程执行、门禁兜底，基本不开 IDE

规则和门禁搭好，剩下的让 AI 跑一夜。

背景

  • 同一产品做 iOS、安卓、鸿蒙
  • Rust 底层 + 各端原生 UI，Bazel 构建
  • 接触 DevEco 约 3 个月，鸿蒙写得少
  • 用了十几年 iPhone，后切到鸿蒙手机

想达成什么

  • 需求快速上线，功能三端大体一致
  • 人不在工位，AI 也能继续干活
  • 提交质量由服务端门禁保证

平时怎么做

  • 先和 AI 对齐方案要点，再让它写 spec
  • 每台电脑开五六个任务，手机接续
  • 不看过程和改动，只看结果
  • 踩坑就写进规则

常用工具

herdr（终端里管理 agent）CodexSuperpowersDevEco CLI鸿蒙模拟器BazelTypeless

和 DevEco 的关系

基本不开 IDE；鸿蒙能力由 AI 通过 DevEco CLI 调用，自己只看到模拟器。没有使用独立 DevEco Code 的描述，未评分。

卡在哪

  • command-line tools 在 Linux 跑不了
  • Rust 支持不好
  • 多个模拟器 title 会乱
  • 三端 UI 细节不一致，没有检查
  • 鸿蒙上架自动化没打通（待核实）

需要什么

  • Linux 服务端能编译、能过门禁
  • 补齐 Rust 支持
  • 内置 agent 不改用户自己的规则和 skill
  • 上架有开放接口可接

个人独立开发者

R3　代表受访者 I04　一个人从想法做到上架，靠 AI 补齐写代码和上架知识

需求和专业都在我脑子里，代码和上架交给 AI 教我。

背景

  • 高校教师，在华为工作近 20 年后内退
  • 做过市场、测试和培训，自称不写代码
  • 华为开发者布道师
  • 2026 年 8–10 月一个人做出 NetLab 并上架

想达成什么

  • 给学生一个能用的华为数通模拟器
  • 全部用仓颉、跑在华为设备上
  • 上架华为应用市场

平时怎么做

  • 和 AI 边聊边打磨需求，不写 PRD
  • 只看架构和技术栈，不看代码
  • 在 DevEco Studio 签名、编译、真机运行
  • 上架问题靠 AI 一步步教

常用工具

华为云码道代码智能体DevEco StudioDeepSeek鸿蒙手机真机AGC

和 DevEco 的关系

卡在哪

  • 上架几次被驳回
  • 码道和 DevEco Studio 来回切
  • 模拟器太吃内存
  • AI 说完成了但发布包有问题
  • 上架截图手工截

  • DevEco 里直接分析问题，不用截图搬运

  • 直连 AGC 看数据
  • 按 API 版本找资料

学习者／兴趣型个人开发者低价值样本

R4　代表受访者 I03　非职业开发者，借助网页版 AI 独立做自用的小应用

看得懂代码，但不想自己写；预览是他最大的依靠。

背景

  • 华为生态总代的 IT 售前，计算机相关专业
  • 大学用 Java 写过 1–2 个安卓应用
  • 考过鸿蒙初级开发者认证
  • 2025 年 8–9 月花不到一周做了一个闹钟应用

想达成什么

  • 做一个自己能控制的提醒应用
  • 在自己手机上用起来

平时怎么做

  • 列功能清单和流程图交给 AI
  • 几个 AI 各出一版，挑报错最少的
  • 对着预览逐个点功能

常用工具

DevEco Studio（预览）DeepSeekKimi豆包Claude

和 DevEco 的关系

卡在哪

  • AI 常没理解功能清单
  • 报错只标红不给原因
  • 不知道有模拟器和真机调试
  • 上架被拒，原因说不清

需要什么

  • 报错就地给出原因和改法
  • 让新手能发现模拟器、真机运行和内置 AI
  • 更多鸿蒙入门资料
