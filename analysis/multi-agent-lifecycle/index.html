主 Agent 与子 Agent：显示、折叠与停止逻辑竞品对照

对比 Claude Code、Codex、Cursor、VS Code Copilot、Gemini CLI、DeepSeek Harness 六款产品如何在对话里呈现子 Agent、子 Agent 的过程放在哪里、默认是否折叠，以及停止主 Agent 时子 Agent 的去留和对话状态。重点回答：主 Agent 停了、子 Agent 没停时，对话应显示什么；是否需要单独停止子 Agent。最后给出 DevEco 的建议。

结论

  1. 停止逻辑由「前台 / 后台」决定，不由产品决定：前台子 Agent 是主 Agent 的一次工具调用，主停即子停；后台子 Agent 脱离了启动它的那次调用，主停后子 Agent 继续跑。Copilot、Gemini CLI 只有前台；Claude Code、Codex、Cursor、DeepSeek Harness 都已有后台。
  2. 主停子未停是常态，不是边界情况：Claude Code 默认把子 Agent 放后台；Cursor 主 Agent 结束不取消后台子 Agent；Codex 按 Esc 只中断当前查看的线程。
  3. 显示形式收敛为「对话里一行 + 独立详情」：对话流里每个子 Agent 一行（名称、当前动作、状态、耗时），完整过程放在独立的子会话 / 线程 / 面板里，且大多只读。
  4. 默认折叠，但「待授权」例外：六家都默认收起子 Agent 过程；Copilot 在子 Agent 需要确认时自动展开、确认后自动收回，是目前处理最细的一家。
  5. 对话状态普遍不聚合子 Agent：主轮次一结束，输入框就回到空闲；后台子 Agent 的状态只在输入框下方的面板或计数里出现。Cursor 因此收到「看起来完成了其实还在跑」的反馈，官方在 3.18 改为子 Agent 跑完前父对话保持「working」。
  6. 会话列表是唯一能看全局的地方，但聚合做法分两派：Claude Code 的 agent view、DeepSeek Harness 侧栏把运行中的子 Agent 算进会话状态；Codex 每个线程各算各的，主线程空闲就显示空闲。子 Agent 一律不单独占会话列表的行。
  7. 单独停止子 Agent 已是标配：Claude Code、Codex、Cursor、DeepSeek Harness 都能停单个子 Agent，Claude Code、Cursor 另有「全部停止」。问题集中在停止不可见：Esc 静默杀掉后台子 Agent、停止后状态显示错、被停的子 Agent 自动复活。

前台与后台决定主停之后子 Agent 的去留

类型主 Agent 怎么等主停止时主轮次结束后采用的产品
前台同步调用 阻塞，等子 Agent 返回结果再继续 一起停取消信号直接传给子 Agent 不存在：子 Agent 先于主轮次结束 VS Code Copilot、Gemini CLI；Claude Code / Cursor 的前台模式；DeepSeek Harness 一次性子会话
后台脱离调用 立刻返回，结果以通知或文件回到主 Agent 按产品而定多数不停；Claude Code 曾随 Esc 一起停 子 Agent 继续跑，主对话已空闲 Claude Code（默认）、Cursor、Codex、DeepSeek Harness 可续接子会话
  • 三件不同的事：主 Agent 本轮结束、某个子 Agent 结束、整个任务完成。只有后台模式会让这三者错开，对话状态需要分别表达。
  • 设计要点：前台模式下「停止」没有歧义；后台模式下必须回答两件事：主停止按钮停不停子 Agent，以及停了之后用户在哪里看到还有谁在跑。

用户反馈

  • Claude Code：Esc 本想插话，却静默停掉了全部后台子 Agent，且不再可恢复；一次会话三次 Esc 丢了五个子 Agent。VS Code 扩展已改为 Stop 只停本轮。
  • Claude Code：中断后子 Agent 已死，主 Agent 仍以为它们在跑并持续等待，用户靠看转录文件的修改时间才发现。
  • Cursor：父 Agent 报告完成，后台子 Agent 还在跑、还在等授权；用户要的不是禁止后台，而是主停时把「还有谁在跑」放到显眼处。
  • Cursor：Stopped、Completed、Starting up 等状态与子 Agent 真实状态不符；Stop All 点了无效，只能重开对话。
  • 共性：用户接受主停子不停，不接受的是停止不可见：不知道停没停、停了谁、还剩谁。

2. 停止作用域

入口停什么停之后依据
主停止按钮 / Esc主 Agent 当前轮次 + 前台子 Agent；后台子 Agent 不停若仍有后台子 Agent，运行条变为「主 Agent 已停止 · 2 个子任务仍在运行」，并给出「全部停止」Claude Code VS Code 2.1.286；Claude Code 终端的反面案例
全部停止主 Agent + 全部后代 + 未启动的委派显示「停止中」直到每个子 Agent 回执；超时列出仍在跑的Ctrl+X Ctrl+K、Cursor Stop All 失效案例
停止此子任务该子 Agent 当前轮次及其后代同级继续；主 Agent 收到「已被用户停止」，不得自动重启Claude Code x、Harness Stop（Harness 不级联后代）、2.1.211 复活修复
  • 需要单独停止子 Agent：需要。用户常常只想砍掉跑偏的一支、保留其他成果；四家已有的产品都提供了。但它不能是唯一途径，必须同时有一次停完的「全部停止」。
  • Esc 不应静默结束后台工作：Esc 是高频插话键。若决定 Esc 也停后台子 Agent，必须在对话里写明「已停止 2 个后台子任务」。
  • 停止不等于撤销：被停子 Agent 已做的改动保留，供审阅或回退。
